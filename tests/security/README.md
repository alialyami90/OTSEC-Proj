# Security tests

Owner: A6. Independent security-boundary tests for the criteria in [docs/verification.md](../../docs/verification.md): V-S5 (monitoring cannot reach state-changing operations), V-S11 (credential canaries), V-S14 (identity mismatch fails closed), V-S15 (hostile device output), and R2.x for engineering access.

## Tests

- `lockdown_test.go`: the node loader's D2-10 lock (lock 1 of 2) and D2-4 on loopback. Ground truth is the rule text of D2-10 and D2-4, not the implementation. IP literals that are not loopback, or are loopback in a refused form (IPv4-mapped, zoned), must fail with `node.ErrNotLoopback`. Names, `localhost` included, shortened or numeric IPv4 forms, brackets, ports and spaces must not load at all. A device-observed endpoint is refused even on loopback. Mutation check: disabling the endpoint check, the listener check, the zone rule or the IPv4-mapped rule, or allowing device-observed, each fails at least one test. Class `simulated`. Nothing opens a connection.
- `collector_lock_test.go`: lock 2 of D2-10, the collector's own check (A3, #97), through `Pipeline.Handle` with a verified register active and a runner that dials. A run to these hosts must be refused `asset_not_enrolled` with a D2-10 detail, the runner must not be called, and listeners must record zero connections: this host's own non-loopback IPv4 address, `0.0.0.0`, `::`, `::ffff:127.0.0.1`, `10.0.0.5`, `192.168.1.10` and `2001:db8::1`. `localhost` and a zoned literal are refused earlier, by C1 at `NewPipeline`. A loopback control must be accepted and reach its listener. Mutation check: accepting any IPv4 in `loopbackLiteral`, or skipping the decision-time check, each fails it. Class `simulated`.

- `asset_clear_test.go`: C7 0.2 `asset.clear_suspension`, the collector side (D2-15, A1 condition 4 on #117), through `Pipeline.Handle` with the admin folder wired as `cmd/otsec-collector` wires it (`protect.CheckDirFor`, then `protect.ReadFileFor`, on every request). The asset starts suspended by one invocation. Each denial must refuse with the expected code and a `collector_seq`, leave the asset suspended in memory and in a reopened state file, keep a run to the asset from reaching the runner, and keep the file's content out of the detail. Denials: a planted file with no request; a request with no file; stale, mismatched or other-asset files and requests; malformed files (case, duplicate key, trailing data, schema, size); a writable, world-readable, linked or hard-linked file; a writable, world-traversable or linked folder; a person, schedule or platform-service principal; an `otsec.authz/0.1` stamp. Controls: a matching clear lifts it durably, and a retry is accepted while a later suspension stays. Mutation check (#117 head): 10 of 11 killed, the survivor an equivalent second layer. Linux only, class `simulated`: the folder check there is the mode, not the Windows DACL.
- `testclock_c6_test.go`: D4-40 point 4 (V-M4), the release build's refusal of the stepped test clock. Both binaries are built without the tag `otsec_testclock` and must refuse `-test-clock` as an unknown flag (exit 2), and hold none of the clock's code. The tagged builds are the control: they take the flag and hold the code. No package compiles a `testclock.go` without the tag. Every test only the tagged build has must match CI's `-run TestTestClock` (C1), so none is silently never run. Mutation check: dropping the tag line from any of the three `testclock.go` files fails it. Class `simulated`. The binaries are built and run here, and nothing else is contacted.

- `uintptr_walk_d6_test.go`: the rule for a test that walks the repository tree (brief P4-PC-1). A directory below the walk's root that holds a `go.mod` file is another module, as the `go` command has it, and the walk does not enter it. The `go` command builds none of it into this module, so the rule hides none of the module's code. On the owner's PC it covers a worktree's copy of the repository and the two local folders that Git ignores, once each has its one-line `go.mod` (HANDOFF.md). Without that file a walker enters the folder like any other: it reads what is there, and fails on a directory it cannot read. Each walker keeps a floor on what it read, so a rule that skipped the module itself fails too. The test runs the walker of `uintptr_args_test.go` on modules built in a temporary directory, with the same breach planted in each place the rule has to tell apart. Three cases:
  - **Another module is not entered.** A breach in it is not reported, and a directory in it that cannot be read does not fail the walk. The control deletes its `go.mod`: the walk then fails, and reports every breach once it can read them.
  - **The rule is anchored at the root, and only a `go.mod` file closes a directory.** The root's own `go.mod` does not close it. A directory deeper in the module that looks like a closed one is read: one named like the other module, `reference`, `tools` or `.claude/worktrees/w`, one that holds a directory named `go.mod`, and one that holds `go.mod.orig`.
  - **An unreadable directory of the module fails the walk,** at the top or deeper, whatever its name.

  Three walkers start at the repository root and carry the rule: this one, `tests/contract/imports_test.go` (its fixture tree holds a nested module, and a directory named `go.mod`) and `contracts/advisory/testkeys_test.go`. That scan covers the repository, not only the module, so it names the nested modules the repository tracks and still reads them, and on a CI runner any other nested module fails it. Mutation check: removing the rule, letting it skip the root, taking a directory named `go.mod` for the file, or skipping an unreadable directory silently each fails a test. Class `desk`.

The V-S5, V-S11, V-S14 and V-S15 tests follow as the collector (A3) and the session adapter (A2) land.
