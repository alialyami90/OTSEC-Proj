# Slice suite (A6, P2-A6)

The end-to-end test of the Phase 2 slice: the recording simulator as a
SEL-751, then the collector, the node store, the forwarder, and an upstream
RELP collector. Each runs as a separate process (D2-3). Evidence class:
`simulated`. Nothing here is hardware evidence (risk 3).

| File | What it is |
| --- | --- |
| `harness.py` | Starts processes that print a JSON `ready` line with their port (`--port 0`). Makes throwaway TLS material with the `openssl` command line. |
| `relp_receiver.py` | The upstream collector for the Windows leg, where rsyslog does not run. RELP over TLS. It accepts only a client certificate that chains to the CA and carries the permitted peer name (`--permitted-peer`: SAN dNSNames, or the CN when there is no SAN; there is no CA-only mode, D2-9). It acknowledges a frame only after fsyncing it, and enforces C6's session rules: open first and once, `commands=syslog` offered, TXNRs from 1 and strictly increasing, no leading zeros, at most 65535 octets. It can drop, reject or `serverclose` the Nth frame (V-S6). Standard library only, and no code shared with the forwarder. |
| `relp_client.py` | A minimal RELP sender used only to test the receiver itself. |
| `test_relp_receiver.py` | The receiver does what the forwarder tests rely on: offers, durable acknowledgement, a pipelined window, `close`, the frame grammar and session rules, fault injection at exactly the Nth frame, mutual TLS on both name paths, and the V-S6 refusals: no certificate, a self-signed one with the permitted name, a CA-signed one for another name, plus a stranger and a SAN that names another node. |
| `test_rsyslog_leg.py` | The Linux leg's collector (rsyslog, imrelp, `tls.authmode="name"`, Direct queue, `sync="on"`) delivers with a durable acknowledgement and makes the same V-S6 refusals. It also records a finding: librelp 1.11.0 accepts a CA-signed certificate whose CN is the permitted peer even when its SAN names another node. |
| `reconcile.py`, `test_reconcile.py` | The 1:1 reconciliation oracle: every SER row the simulator printed against the C6 messages a receiver stored (timestamps, order, no duplicate, no loss, `evc="simulated"`), with mutation tests showing each check fails on a broken input. |
| `test_slice_e2e.py`, `slicehelper/` | **The slice end to end on the real binaries.** The simulator as the SEL-751, then `otsec-collector`, then `otsec node`, then the RELP receiver over mutual TLS. `slicehelper` writes the node configuration through A5's `nodeconfigtest` (D2-6) and the collector's `collector.json` with the register on main, signed by a key made for the run. It also creates the collector's stores an hour in the past, so the fresh-state floor has passed, and stands in for the administrator who installs the credential: sealed to the published install key, sent over the socket, with the secret taken from the environment. Two scheduled runs. The checks: every Figure 10.16 row arrives exactly once, byte for byte, with its time text (reconcile); the second read forwards nothing new; the recording check passes (read-only lines only, one session at a time, one password, QUI last); the password is in no file, log, forwarded message or process argument. About 140 s. Linux; the Windows leg is the PC run. |
| `test_slice_identity_e2e.py` | **Identity, suspension and the clear, end to end on the real binaries** (AP-27, D2-15, D2-17). Three runs at one address, the simulator replaced between them. First, an ID reply without STX and ETX: reported upstream as `collection.run status=failed`, no suspension on either side (A2 #122). Second, another FID: `identity-mismatch`, suspended on both sides under the same ref, the run's invocation. Third, the device put right and the administrator's `clear-suspension.json` (0440 in the 0550 `config/admin` both services read): the node clears, sends the collector its `asset.clear_suspension` (A5 #120), and collects. The checks: no `ACC` and no auth event before a matching ID; no session and nothing collected while suspended with no file; both sides clear; every row once (reconcile); the recording check passes on all three recordings. About 250 s. Linux. |
| `test_slice_interruptions_e2e.py` | **V-S6 (and V-S4's buffer that changes between reads), end to end on the real binaries.** The simulator's SER buffer grows four rows per read and renumbers every row (`ser="grow"`, SYNTHESIZED). A seeded scheduler kills, every 5 to 40 s, the receiver, the node (half of those two timed mid-burst), the simulator or the collector (those two only between sessions), and restarts each. Then two clean runs. The checks: every row the buffer held arrives under exactly one event ID (`reconcile_grown`); a resent event ID carries the same bytes; every confirmed event is in what the receiver fsynced, with no gap; the events received again after each break are at most the RELP window (128), and none without a break; the recording check; the password nowhere. `OTSEC_SLICE_INTERRUPTIONS` (default 6, about 7 minutes; the soak is 100) and `OTSEC_SLICE_SEED`. Linux. |
| `test_slice_failures_e2e.py` | **V-S12, end to end on the real binaries.** Seven slices side by side, one fault each: unreachable, wrong password, a device 20 s late, SER hanging inside its message, a malformed SER row, the receiver down, and an adapter-evidence quota with room for one run. Each must show its own failure in `otsec health` (the last run's code or an alarm) within 60 s of the failing run (125 s of the kill for the receiver, by the node's own 60 s rule), and no failing run is shown or reported as ok. In the store case the receiver is down too, since the node prunes confirmed events while it runs (#135). The late device must suspend nothing (D2-19). The late device and the hung SER share `failed.timeout` and are told apart by the detail health prints (#135, #137), which the test pins. The recording check passes for each of the seven. About 130 s. Linux. |
| `test_slice_floor_e2e.py` | **The floor held from `=>` to QUI (D2-16, D2-20), end to end.** With the simulator keeping Level 1 for a new connection (`--profile-inherit level`), the collector is SIGKILLed after `=>` and before QUI, then restarted. The checks: its state keeps `level_open` and the floor; the next runs are refused `rate_limited`; no second session reaches the device; the recording check's only finding is the session the kill left at Level 1. About 190 s. Linux. |
| `test_slice_time_e2e.py` | **V-S3's negative cases, end to end.** Two slices: Figure 10.16 (`Time Source: Internal`) and a SYNTHESIZED fall-back hour (`ser="dst"`: the same wall time twice and time going backwards, under `Time Source: External`). The checks: no offset invented (`doff="unknown"`, `dbasis="none"`, no `dutc`, and the HEADER is the receive time); `dt` and `dwall` as printed with no reordering through the fall-back; `tsync` stays `unknown` for either source and no `dacc` (SEL-751 documents no unsynchronized flag, Table 7.16); the recording check passes for both. About 70 s. Linux. |
| `test_slice_buffer_e2e.py` | **V-S4, end to end: a SER buffer that changes between reads.** The simulator serves a SYNTHESIZED script of seven reads, one per run (`ser="script"`): Figure 10.16; its oldest rows gone and two identical new rows; the buffer cleared; one more row; a middle row removed; repeating chatter; the chatter again, overlapping at two offsets. The checks, against the script: the number of new events per read (8, 2, 2, 1, 1, 4); each event is its row as first printed; both identical rows kept under two event IDs; exactly one `ser.gap` at the clear (0 removed) and one at the removal (1 removed), with the rows after the clear `gap-before`; the ambiguous read raises one `ser.alignment-ambiguous`, keeps the smallest overlap and flags the rows it may repeat `possible-duplicate` (C1 `align.go`); the recording check. About 7 minutes. Linux. |
| `test_slice_store_full_e2e.py` | **V-S9, end to end: the evidence store filled.** The adapter-evidence quota leaves room for a quarantine and 400 KiB, the receiver is down, and the SER buffer grows 100 rows per read (`ser="grow"`). The checks: `collection-quarantine-room-low` comes no later than `collection-no-quarantine-room`; no session opens while the class is full, including after the node is SIGKILLed and restarted still full; once the receiver is back, with no operator action, runs resume and the last run is `ok`; every row the buffer held arrives under exactly one event ID, so nothing unforwarded was evicted; the recording check passes across the fill, the kill and restart, and the resumed runs. About 8 minutes. Linux. |
| `test_slice_gtinj_feed_e2e.py` | **V-M4's feed on the stepped test clock (D4-40 item 4).** The node is built with `otsec_testclock` and run with `-test-clock`. `slicehelper setup -gtinj-events` adds the GT-INJ Syslog asset, which sends from 127.0.0.4, and an event baseline with the series' params. The harness steps the clock to each of the 1,175 Syslog events of `tests/integration/gt_inj/events.json`, sends it, and waits until it is stored before the next step. The checks, against C6's own read of the store: every event is stored once, in order, bound to the GT-INJ asset, with its sent bytes, with `received.utc` equal to its scheduled `received_utc`, and with the `pri` and `msg` native fields the detector's type key is built from. A node off the test clock fails the time check. **The alarm half:** at `period.baseline_ack` the harness steps the clock until node status shows the learnt baseline as recorded, acknowledges it with a signed `node.baseline_ack` of kind `event` (`slicehelper admin-file -kind baseline-ack`; under `-gtinj-events` the admin key also lists that kind, and the collector enrols the GT-INJ asset), and steps on until it is active. After the last event the clock goes to `period.test_end`. The `baseline.departure` health events in `platform/health` then go to `tests/integration/gt_inj/alarms.py`'s `check()` for the `gt-inj-syslog` asset: the 10 expected Syslog alarms, none before the acknowledgement, none citing a control event, and recall and precision in the log. Two more nodes run: one fed the same series, whose alarms must equal the first's in every field and cited event and must pass the oracle on their own, and one fed `events-heldout.json` in place of the test period, which must raise no departure alarm and show no refused or late event in status. All three must store the same baseline bytes (D4-45, F-020). **The untagged node (D4-40 item 4):** a fourth node, the release build on the wall clock with short params, sends 11 events and records a baseline from those up to T (D4-45), makes it active on a signed acknowledgement, and then raises exactly a new-type alarm and a repeats alarm, citing their events, plus a time alarm on the first burst row when the wall clock has crossed into a UTC hour the period never saw (F-023). The SER half is `test_slice_gtinj_ser_e2e.py`. About 7.5 min. Linux. |
| `test_slice_gtinj_ser_e2e.py` | **V-M4's SER half on the real binaries (D4-47).** The node and the collector are built with `otsec_testclock` and run with `-test-clock` on one clock file. `slicehelper setup -gtinj-ser` gives the slice's asset an event baseline with the series' params. The simulator serves its SER buffer from a file (`--profile-ser file`). Before each of `tests/integration/gt_inj/events-ser60.json`'s 913 reads, the harness writes the newest 1,024 rows received so far, each printed with its `events.json` time. It then jumps the clock to the read's time and waits until the rows are stored and the run has ended. The gap-before read's buffer holds only its own rows. The series is shifted by whole days, to after the wall clock where the credential install is signed, and the alarms are shifted back for the oracle. The acknowledgement is signed at the shifted `baseline_ack`. The checks, against C6's own read of the store: every row is stored once, in order, with `received.utc` equal to its read time and the series' alignment. The period ends at 2026-11-16T06:34:08Z with 769 rows (D4-45). The baseline is active only on the acknowledgement. The `baseline.departure` events pass `alarms.py`'s `check()` for `gt-inj-ser60`: the 6 expected alarms. The adapter evidence quota is raised to 512 MiB, because each read keeps the whole buffer. About 30 min, in its own `integration-long` leg with a 50-minute limit. Linux. |
| `test_slice_config_changes_e2e.py` | **V-M2 on the real binaries, with the stepped test clock on the node and the collector (D4-40).** Each of the 21 changes of `tests/integration/gt_inj/config.json` runs on its own node and simulator (`--profile-config-run`, SYNTHESIZED replies for the SHO forms the manual does not print). `slicehelper setup -config-every 75s` schedules `sel.config.read_all` on the slice asset, enrols a second asset for the other-device case, and adds an operator key that may not sign `node.change_approval`. The harness jumps the clock to each step of the series' timeline (R0, `baseline_ack`, Rm, the change, R1, one more read). It signs the configuration acknowledgement, and the change's approval with the issue time and window the series gives, by the administrator or, for the non-approver case, the operator. The change is injected through `--profile-settings`, or, for a non-semantic change, by restarting the simulator with the other SHO layout. The checks, per change: the R0 snapshot is the acknowledged baseline and Rm finds no difference; `config-unapproved-change` and an `unapproved_change` record exactly when `expect.alarm`, at R1; an approved change's R1 record links its approval's seq, which comes before it in the chain; a non-approver's approval is refused at the authority check and its `collector.request` denial recorded; a backdated approval comes after R1 in the chain; both snapshots and the difference are stored, and the difference's changes equal `expect_changes`. For a non-semantic change (D4-46): all three reads give `no_difference` with no change held, there is no difference record, and only the group sections' hashes differ. `slicehelper verify-audit` verifies the audit chain, and fails it with the approval record deleted or edited. **V-M3 for the SEL-751:** every session the device saw is the signed register's `sel.config.read_all` over Telnet, and the untagged `otsec node` refuses at start a configuration that names a method or an FTP endpoint. About 4 min. Linux. |
| `test_slice_mixed_register_e2e.py` | **A mixed node on the real binaries (C5's `register_versions`, #466).** `slicehelper setup -snmp-port` adds a SEL-2731M polled over SNMPv3 beside the slice's SEL-751: the SEL-751 runs under `register_version` 5 and the SEL-2731M under `register_versions["sel-27x1-rstp"]` 1, and the collector holds both packages, signed by the run's release key. No SNMP agent listens and no SNMPv3 credential is installed, so the SEL-2731M's run is refused at the credential (`credential_unusable`, decideRun step 10), after its register check (step 5); the SEL-751 collects all 8 rows. The control (`-snmp-unlisted`) leaves the profile out of `register_versions`: the SEL-2731M's run names 5 and is refused as `register_version`, and the SEL-751 still collects. About 2 min. Linux. |
| `test_slice_vm7_e2e.py` | **V-M7 on the real binaries: R9 on the SEL-751 over GT-ADV (P4-3-C6).** Each of GT-ADV's eleven device-read rows runs on its own node and simulator: `slicehelper setup -gtadv-row` declares the row's FID on the slice asset (the simulator serves it), turns `asset` and `applicability` on with advisory test key 0 as the anchor, and leaves GT-ADV's eight advisories, signed as set `gt-adv` version 1, in `admin_dir`. | `test_slice_vm8_sets_e2e.py` | **V-M8's set cases on the real binaries (P4-3-C6).** One node built with `otsec_testclock` on the wall clock, R9 on with two advisory anchors, test key 0 active and test key 2 revoked (`slicehelper setup -vm8`). `slicehelper advisory-file` leaves one administrator's file at a time in `admin_dir`, built from GT-ADV's set with one thing wrong, and prints its SHA-256 and the C11 code it must get. | `test_slice_vm8_paired_e2e.py`, `netcapture.py` | **V-M8's paired runs: applicability never probes a device (D4-49 Q12, D4-50).** Three runs of the same `otsec_testclock` build on one simulator port, each stopped after its second `sel.ser.read_all` session: A1 and A2 with the asset module on and R9 off (`slicehelper setup -asset`), the A/A pair first, then B with R9 on and GT-ADV's set (`-gtadv-row D1`). | `slicerun.py` | The shared runner for the end-to-end files: builds the binaries (or shares another run's), starts the four processes, kills and restarts any of them, replaces the simulator at the same address, writes the administrator's file, reads `otsec health`, the collector's state, and what the receiver got. `slicehelper setup -quota class=bytes` changes a store quota. `node_tags` and `node_args` build and run a tagged node (the test clock). |
| `conftest.py` | `need()`: a check that cannot run skips, or fails when `OTSEC_SLICE_REQUIRED=1`. |

The `test_slice_*_e2e.py` files drive the product binaries. In CI the three long ones (interruptions, buffer, store full) run in `ci.yml`'s `integration-long` job, one job per file; the `integration` job ignores exactly those three, which keeps it under its 20-minute limit.

## Requirements

- Python 3.12 or later, with `pytest` and `asyncssh==2.24.1` (the simulator's SSH transport).
- `openssl` on `PATH` for the TLS tests. Git for Windows ships one.
- Go, to build the binaries, once they exist.
- The Linux leg also needs `rsyslog` with `imrelp` and TLS support (`rsyslog`, `rsyslog-relp`, and `rsyslog-openssl` or `rsyslog-gnutls`).

## Run

```
python -m pytest -q tests/integration/slice
OTSEC_SLICE_REQUIRED=1 python -m pytest -q tests/integration/slice   # integration job and exit-gate runs
```
