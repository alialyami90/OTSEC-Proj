## What C10 fixes, and where each rule comes from

| Rule | C10 | Source |
| --- | --- | --- |
| SER key | Element and state as printed (`normalized.subject`, `normalized.value`). A row the parser did not read, such as the relay's own "Relay Settings Changed" or "Relay Powered Up" (S22 p. 10.39), is keyed on the template of its native bytes (digit runs replaced, so the row number and time drop out). A row whose bytes are not on the event is keyed on its `record_sha256`, a type of its own that alarms as new once active. So every stored SER row has a key and none is left out of learning or alarms (`TestUnparsedSERRowIsKeyed`, `TestRelayMessageRowKeysAsC10Says`). | verification.md, "R4.8 observation period and measures"; B2 confirmed against S22 Fig. 10.16; B2's finding and B1's condition on #254 |
| Syslog key | Facility and severity from `pri`, and the template: `msg` with each digit run replaced by `#`, identified by its SHA-256. A message with no readable PRI gets `pri-absent`. `app_name`, the tag and the RFC 5424 MSGID are left out, so a sender that reuses one MSGID for different messages gets one type per template (`TestMSGIDIsNotInTheKey`). An earlier draft keyed on the MSGID when present, as `docs/verification.md` (R4.8) then said. B1 dropped it in D4-9: a sender chooses its MSGID, so a compromised sender could hide a new kind of message under a known one. Without a `msg` field, the whole record is the message. | D4-4 item 4; D4-9 (no MSGID) |
| Excluded events | Platform events, kinds other than `ser` and `syslog`, and `asset-unresolved`. The last are counted only in a site-level total kept by the node. | A6's invariant; handoff |
| Catch-up | SER rows aligned `first-read` or `gap-before`, and the first good read after a V-S12 failure, are `type-only`. They count for the type set and new-type only, not for window, rate or hour learning, and the repeats, rate and time rules skip them. Repeats runs on received time, its window is (t − `repeats_window_s`, t], and an occurrence exactly at the absence deadline is in time. Limit: a burst during an outage is not alarmed as repeats; a device-time repeats rule may follow in a later minor once the offset is known. | D4-4 item 2 as D4-9 amends it (B6's finding, B1's ruling on #254); `first-read` from B4's ack (#229), accepted by A4 |
| Repeats | The same `record_sha256` again is an occurrence. | P4-A4 brief |
| `possible-duplicate` | Matched against the previous read's alignment keys only, one to one, never within the current read (`PossibleDuplicates`). | D4-4 item 3 |
| Clock | Rate and time run on `received.utc`. Device time is allowed only for the time rule, and only with a known offset. `Params.time_clock` and each alarm's `clock` say which was used. | D4-4 item 1 |
| Hash | `sha256:` and the hex SHA-256 of the stored bytes, exactly as stored (`Hash`). C9 uses the same rule. | D4-4 item 5; B2 |
| Alarm transport | A C4 platform event of type `baseline.departure`, so it stores and forwards with no C4 or C6 change. `Alarm.Health` and `AlarmFromHealth` convert it each way. | B5 agreed |
| Alarm bounds | One alarm per (asset, rule, key) per `alarm_hold_s`. At most `max_alarms_per_hold` per asset, then one `baseline.alarms-held`. At most 32 event IDs in each list, plus a total. The key is the event-type key, which holds no read ID or time, so the hold needs nothing from C9 (B1, on #247). `alarm_hold_s` is at least 3600 and `max_alarms_per_hold` at most 8. `baseline_value` and `observation` are at most 256 bytes each, and a SER element and state at most 128. So the worst alarm's health body is 20,586 bytes encoded, under `MaxAlarmBytes` (24 KiB, `TestWorstAlarmFits`). | B5's asks on #254: the platform class refuses new events when full |

## Choices this draft makes (please challenge them)

1. **The rate bound is one value per type**, not one per hour of the day: the larger of `rate_min` and `max_per_bucket` × `rate_factor_pct` / 100, rounded up (`RateBound`). The time rule already covers time of day. Buckets run from the Unix epoch, on received time. For a polled SER source, `rate_bucket_s` must be at least the collection interval. The learner enforces that, because the contract does not know the interval.
2. **The repeats rule is taken literally** from verification.md: more than `repeats_n` in `repeats_window_s`, where the type's `max_per_window` was below `repeats_n`. A type whose learnt maximum is already `repeats_n` or more never raises a repeats alarm. Any rise in its rate is the rate rule's job.
3. **Periodic.** A type counts as periodic when it has at least `periodic_min_occurrences` full occurrences and every gap between them lies within `periodic_spread_pct` of the median gap. The median is the upper middle of the sorted gaps, and it is the interval. The absence rule alarms when the type is missing past interval + `Tolerance(interval, absence_tolerance_pct)`, which rounds up. Learning a period and tolerating jitter are separate parameters, as in B6's GT-INJ (#251): one percentage cannot be both tight enough to find a period and loose enough to ride out jitter.
4. **Hours are UTC hours of `time_clock`.** Daylight saving moves a site's local day by one hour. This is stated as a limit.
5. **The type cap and the size cap.** `max_types` must not exceed 4096, and a stored baseline must not exceed `MaxBytes` (512 KiB), C10's own cap, which is set at or below the configuration class's `MaxRecordBytes` in C5 0.4 (#246, now 1 MiB provisional), or the node's lower cap. A type takes 274 bytes (a quiet SER type) to 629 bytes (a busy Syslog template type with every hour populated) encoded compact, 1,011 indented (desk measurement), so 4096 types would take 1.1 to 2.6 MB: the byte cap is the one that binds. The baseline is stored compact (`Encode`). Types past either cap are left out lowest count first, ties by key, and counted in `counts.types_overflow`. Once the baseline is active they are new types, so a flood during learning stays visible.
6. **All integers.** Durations are in seconds and factors in percent, so the rules use no floating point and give the same answer everywhere.
7. **Alarm load is bounded per asset.** It is at most (8 + 1 held) × 24 KiB an hour. B5 asked for 16 KiB, but the worst case Validate accepts is 20,586 bytes once HTML escaping, 128-character streams and 20-digit seqs are counted, so the cap is 24 KiB rather than a smaller list. B5 sizes the platform quota and a node-wide cap from it (P4-A5).

## Open before merge

- B1: the C10 row in `contracts/README.md`, which is B1's file.
- B6's independent contract tests under `tests/contract/` (standing dependency).
- B6's GT-INJ series (#251) keys Syslog by msgid. Under D4-9 it must differ by template, and `docs/verification.md` line 326 must drop the message ID (B1 asked B6).

The learner's default parameters follow B6's GT-INJ proposal (#251), as values the learner records in every baseline, not C10 constants. They are `repeats_n` 5 in `repeats_window_s` 600, `rate_bucket_s` 3600 (UTC clock hours, since buckets start at the Unix epoch), `rate_factor_pct` 300, `rate_min` 2, `periodic_min_occurrences` 11 (B6 requires 10 gaps), `periodic_spread_pct` 10 and `absence_tolerance_pct` 50. The detector reads time only from events and an injected `now`, so B6's acceptance test replays by `received_utc`.

## Not in C10

The lifecycle (recorded, awaiting acknowledgement, active, re-learn) belongs to the node and C5 0.4. The learner, which runs in `modules/detection/` after C5 0.4, is also out of scope. So are network baselines (R6) and machine learning.

## Limits

- The digit rule merges messages, including RTAC tags, that differ only by a number (D4-4 item 4).
- The Syslog key depends on the otsec-syslog parser's field names. `TestSyslogGoldensKeyAsC10Says` in `modules/telemetry/normalize` ties the two together.
- A synthetic false-positive rate says nothing about a real device (V-M4).

## Evidence (desk, Linux, Go 1.26.10)

- `go test ./contracts/baseline ./modules/telemetry/normalize` passes. Its tests include the key over C4's own goldens and over the parser's three documented Syslog examples.
- Mutation checks: each of the following breaks a named test.
  - digits kept in the template;
  - catch-up alignment ignored;
  - a possible-duplicate match not spent;
  - comparison within the current read;
  - the device clock allowed for any rule;
  - `collected_s` unchecked;
  - facility and severity swapped;
  - the `asset-unresolved` flag ignored.
