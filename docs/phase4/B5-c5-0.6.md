# C5 0.6: the hold codes `acknowledged-difference` and `restored-difference` (D4-18, D4-19)

B5, 2026-10-28. Two additions to `otsec.store`, ruled by B1 in D4-18 (#306) and D4-19 (#310), after B6's review of #305.

- **New code.** `HoldAcknowledgedDifference` = `"acknowledged-difference"` joins `baseline` and `unapproved-difference` in the closed `HoldCode` set and in `HoldReason.Validate`. `Ref` stays a C8 record: the `config.change_detected` that names the snapshot and the difference.
- **`restored-difference` (D4-19).** The same, for a change whose alarm ended by a return to the baseline (`config.baseline_restored`), kept separate so the holds table shows how each alarm ended. `Ref` is the `config.change_detected` record for both codes.
- **Why.** A configuration acknowledgement ends a change's alarm. The snapshot and the difference are the evidence of that change (R3.5, R3.6), and only the `unapproved-difference` hold kept them from retention. So an acknowledgement changes the reason of those holds to `acknowledged-difference` and does not release them. Nothing ends that hold until B1 rules a retention rule for configuration evidence; the node never releases it to make room.
- **Unknown codes.** From 0.6 a reconcile that meets a hold code it does not know keeps that hold unchanged (no release, no new reason) and raises `store-holds-reconciled` saying so. A store written by a later node is not unpicked by an earlier one.
- **Compatibility.** The `holds` table stores the code as text, so a 0.5 database needs no migration. There is no reconcile on `main` before this one, and it keeps hold codes it does not know (#307 shows `main` keeps them too), so no shipped build takes a hold of a new code for one the C8 records do not justify. The release note still says: do not roll a node back to a build that predates 0.6 while it holds `acknowledged-difference` or `restored-difference` records, because a build that does not know the codes could not tell them from holds to remove.
- **Tests.** `contracts/store/v06_test.go`: the code is valid, a reason without a C8 record or with a code outside the set is refused, and a configuration record commits with the new hold.
