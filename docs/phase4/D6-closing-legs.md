## 3. Finding (F-026): the forwarder's rsyslog tests had never run in CI, and failed when first made to run. Fixed in #620

This is the extension D1 added to the brief on 2026-11-11. D6 proposed the number, and `main` now cites it (D4-84, `ci.yml` and `modules/telemetry/forward/rsyslog_test.go`). `docs/verification.md` is not changed by this PR, so the findings log does not hold it yet.

**The state now, after #620 (P4-D4-F26, merged as `8e29891e`): the three tests run in the Linux `go` job on every pull request, cannot skip there, and pass.** The bullets below from "What was claimed" to "What it was" are the record of 2026-11-11, before that fix.

- **What was claimed.** The matrix cell of R4.6 (PR #613) says that the forwarder meets a stock rsyslog at unit level, in `TestRsyslogExactlyOnce`. The Phase 2 status table lists `TestRsyslogKilledMidStream` and `TestRsyslogExactlyOnce` under V-S6.
- **What `main` did then.** `modules/telemetry/forward/rsyslog_test.go` (`needRsyslog`) skips its three tests unless `rsyslogd` and `imrelp.so` are on the machine, and fails them instead only when `OTSEC_RSYSLOG_REQUIRED=1`. No workflow set that variable. The Linux `go` job installed nothing and ran `go test ./...` without `-v`. On `main` at `cdbf61e8` ([run 42911349143, the Linux `go` job](https://github.com/alialyami90/OTSEC-Proj/actions/runs/42911349143/job/130162506936)) the log shows no install step and `ok otsec.local/otsec/modules/telemetry/forward 5.311s`, which does not say whether a test skipped.
- **Shown directly.** On this PR at `4776b0da` ([run 43023340359, the Linux `go` job](https://github.com/alialyami90/OTSEC-Proj/actions/runs/43023340359/job/130531735153)), a temporary step ran `go test -count=1 -v -run Rsyslog ./modules/telemetry/forward/` on the runner as it comes, which was the state of `main` then. The runner has `/usr/sbin/rsyslogd` and no `imrelp.so`. All three tests skipped: `TestRsyslogExactlyOnce`, `TestRsyslogKilledMidStream` and `TestRsyslogRefusesAnotherNode`, each with "rsyslogd with imrelp not found". **So these tests had not been running in CI.**
- **Made to run, they failed.** In the same job, after `rsyslog-relp` was installed (rsyslogd 8.2512.0, librelp0 1.12.0-1: the `go` job, on `ubuntu-latest`, which is now `ubuntu-26.04`) and with `OTSEC_RSYSLOG_REQUIRED=1`, all three failed after 10 s each with "rsyslogd did not listen". The test printed no output of rsyslogd.
- **Why.** On `1a9439f3` ([run 43025443153, the Linux `go` job](https://github.com/alialyami90/OTSEC-Proj/actions/runs/43025443153/job/130538874480)) a temporary step started the installed `rsyslogd` against a configuration in a temporary directory, as the test does. rsyslogd answered "could not open config file ... Permission denied", and the kernel log has AppArmor's denial: `apparmor="DENIED" operation="open" profile="rsyslogd" name="/tmp/.../rsyslog.conf"`. A copy of the same binary, run from the temporary directory, opened the file. This is the confinement that `tests/integration/slice/harness.py` (`rsyslogd()`) already works around for D6's own rsyslog tests by running a copy.
- **What it was, and what it was not.** It was a failure of the test's set-up on the hosted runner: rsyslogd never started, so the forwarder was not exercised and no forwarder behaviour was shown wrong. It was not evidence against the product. It did mean that no CI run stood behind the unit-level claim. Whether the tests passed on a machine of A4's in Phase 2 is not something this note can check.
- **The fix, #620 (D4, merged as `8e29891e`).** The tests now run a copy of the installed `rsyslogd` and check the copy's SHA-256 against it, as D6's harness does. The Linux `go` job installs `rsyslog` and `rsyslog-relp`, prints their versions and the binary's hash, checks the packages' files with `dpkg --verify`, sets `OTSEC_RSYSLOG_REQUIRED=1` for `go test ./...`, and runs the three tests once more with `-v`. On #620's head `088bda8b` ([run 43037437203, attempt 5, the Linux `go` job](https://github.com/alialyami90/OTSEC-Proj/actions/runs/43037437203/job/130689982869)) the log shows `--- PASS` for `TestRsyslogExactlyOnce`, `TestRsyslogKilledMidStream` and `TestRsyslogRefusesAnotherNode`, against rsyslogd 8.2512.0 with librelp0 1.12.0-1.
- **This branch.** It carried the install step, the variable and `fail-fast: false` first, as D1 authorized, and its Linux `go` leg was red from `4776b0da` to `58f2527f` on those three tests alone. It then took `main` by a merge. The `go` job is now `main`'s, word for word, and this PR adds nothing to it. `modules/telemetry/forward/` was never changed here: it is D4's.
- **Which rsyslog met what.** Named by job, because the two differ:
  - The `go` job (`ubuntu-latest`, now Ubuntu 26.04): the forwarder's own tests, in-process, against rsyslogd 8.2512.0 with librelp0 1.12.0-1.
  - The `integration-long` jobs (`ubuntu-24.04`): the real node, end to end, in the legs of section 1, against rsyslogd 8.2312.0 with librelp0 1.11.0-1ubuntu3. The `integration` job has the same image and version, for the negative control and `test_rsyslog_leg.py`, where D6's own client is the sender.
  - No run has the real node forward to rsyslogd 8.2512.0.
- **The Windows leg was cancelled with it.** On head `91b44e58` ([run 43026581350](https://github.com/alialyami90/OTSEC-Proj/actions/runs/43026581350)) `go (windows-latest)` has no result: the `go` matrix had no `fail-fast: false`, so the red Linux leg cancelled it 13 s after failing. The same Go tree passed on Windows at `18f01b1d` ([job](https://github.com/alialyami90/OTSEC-Proj/actions/runs/43022774150/job/130529825391)); the commits between change only Linux steps of `ci.yml` and this file. D1 then authorized `fail-fast: false` on that matrix, and the commit after `91b44e58` sets it.
- **How the slice legs avoid the same denial.** They never run `/usr/sbin/rsyslogd` itself. `harness.rsyslogd()` copies that binary once into a temporary directory and runs the copy (`rsyslogrun.start_rsyslogd` uses it). AppArmor attaches the `rsyslogd` profile by path, so the copy is not confined, and it loads imrelp from the same compiled-in module directory. A test checks that the copy's SHA-256 is the installed binary's.
- **For the matrix.** R4.6's cell may cite `TestRsyslogExactlyOnce` as unit-level evidence from #620 on, with its run, and not before. For the criterion itself it should cite the R4.6 leg.

## 4. Other things seen

The `integration` and `integration-long` jobs are pinned to `ubuntu-24.04`. - **The four legs are kept out of the `integration` job by `tests/integration/slice/conftest.py`** (`collect_ignore`), not by more `--ignore` flags in that job, because the brief allowed no change to another job. Its count went from 163 to 167 tests, the four being `test_rsyslogrun.py`'s, and its pytest time was 17 min 27 s, against 17 min 28 s on `main`. D1 accepted this on #619, on one condition: a leg that is skipped or not collected must never pass silently. It cannot. Each of the four files is named by exactly one `integration-long` entry, and pytest collects a file named on its command line whatever `collect_ignore` says: the legs ran 7, 9, 10 and 6 tests on `91b44e58`. If a file were not collected, pytest would run no test and exit with code 5, which fails the job. `OTSEC_SLICE_REQUIRED=1` is set for the whole job, and each leg's fixture goes through `need()`, which fails where it would otherwise skip. None of the four files has a skip mark or an expected failure.
