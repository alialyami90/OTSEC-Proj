# C9 0.4: a difference is bounded (C2, 2026-11-04)

C2's proposal for `otsec.config/0.4`, with C1's go (2026-11-04, after C2's review of #390). Evidence class: `desk` for the measurement, `simulated` for the tests. No relay was read.

## 1. The gap

C9 0.3 bounds a snapshot (D4-25) but not a difference. A difference carries both values of every changed setting, plus about 80 bytes of field names for each change. So it can be more than twice the size of either snapshot. A difference too large for one record cannot be stored. In #390 the read would then raise `collection-evidence-not-stored` instead of `unapproved_change`, write no `config.change_detected`, and leave a snapshot that rule 3 can never remove. Each later read would do the same.

## 2. The measurement

`contracts/config/testdata/difference_max.py` takes the 24 `SHO` forms' settings from S22's settings sheets with `count_settings.py`: 8,734 settings with 51,381 bytes of names. A difference in which every setting is present in both reads and every value changed is:

- 774,529 bytes without the values: the header, plus each change's class, kind, name and sensitive mark;
- plus both reads' values. Each read's values are at most the run's 512 KiB of received bytes, less each setting's name and printed separator. The sheets' widths (1.86 MB in all) do not bind.

The bound is `MaxDifferenceBytes` = `RecordCap` less `RecordHeadroom`, 1,507,328 bytes. A difference has no capture.

| Separator a setting | Values a read | JSON escape | Difference | Over the bound |
| ---: | ---: | ---: | ---: | ---: |
| 4 | 437,971 | none | 1,650,471 | 143,143 |
| 4 | 437,971 | 10% | 1,738,065 | 230,737 |
| 5 | 429,237 | none | 1,633,003 | 125,675 |
| 5 | 429,237 | 10% | 1,718,850 | 211,522 |
| 6 | 420,503 | none | 1,615,535 | 108,207 |
| 6 | 420,503 | 10% | 1,699,635 | 192,307 |

These are the six rows `difference_max.py` prints. So **the worst case does not fit**: 1,615,535 to 1,738,065 bytes, which is 7.2% to 15.3% over the bound. It needs every setting of every form in one read, which no single model prints, with every value changed at once, for example a relay loaded with another relay's settings. A realistic large change fits: in Go, 8,500 settings of 30 characters, every one changed, encode to about 1.22 MB (`TestDifferenceSizeBound`).

## 3. What 0.4 does (built here)

- **`Difference.Encode`** is the difference's one stored form, as `Snapshot.Encode` is the snapshot's: compact JSON, no HTML escaping, no trailing newline. `Digest` over its bytes is C8's `difference_digest`. The node's `encodeDifference` in #390 writes the same bytes, so it can switch to `Encode` with no change to what is stored.
- **`MaxDifferenceBytes`** = `RecordCap` less `RecordHeadroom`. `Difference.Validate` refuses a larger one, wrapping `ErrTooLarge`.
- **`Compare` still returns the difference** with that error. The change is real, so the caller can still name it (`ChangesDigest`) and alarm on it. It just cannot be stored as one record.
- The contract is `otsec.config/0.4`. Readers accept 0.3 documents, which is the same major. The goldens are regenerated, and the transcripts are unchanged.

## 4. The open question for C1: what the node records for an oversize change

0.4 makes the oversize case fail visibly. It does not yet say what the node records. Three options:

- **(a) Record the change without a stored difference. This is my recommendation.** On `ErrTooLarge`, the node writes `config.change_detected` with `changes_digest` from the returned difference and no `difference_digest`, and holds the read's snapshot as it would hold a difference. The evidence stays complete: the baseline is held `baseline`, the read is held, and `Compare` is a pure function of their stored bytes, so the difference can be recomputed whenever it is needed. This needs C8 to allow `config.change_detected` without `difference_digest` when a reason says the difference was too large (C3). C9 needs no further change.
- **(b) A difference without values.** Each change names its class, kind and setting, and the values are read from the two held snapshots. The worst case is then 774,529 bytes, which fits. But this is a format change, C9 0.5. And `changes_digest` must still cover the values, otherwise a second, different change to the same settings would look like the same change, so the digest could no longer be computed from the stored difference alone. That touches C8's meaning.
- **(c) A difference with only the new values.** The old values come from the held baseline. The worst case is about 1.26 MB, which fits. It has the same digest problem as (b), and it is also a format change.

(a) changes the least and loses nothing: the change is alarmed and the evidence is kept. (b) and (c) change a stored format for a case that needs a whole relay reloaded at once.

## 5. Tests

- `TestDifferenceSizeBound`: two valid snapshots of 3,000 settings make a difference over the bound. `Compare` returns it with `ErrTooLarge`, with all 3,000 changes and a `ChangesDigest`, and `Validate` refuses it. 8,500 settings of 30 characters fit, and `Encode` round-trips through `DecodeDifference`. A difference at the bound is a record within `RecordCap`.
- `TestDifferenceEncode`: `Encode` is compact, has no newline, and keeps `<` unescaped.
- Every existing C9 test passes on the regenerated goldens.
