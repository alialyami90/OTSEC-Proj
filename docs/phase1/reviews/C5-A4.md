## Outcome: accepted

Re-checked at 2ef46a2 (2026-10-24). All four changes are resolved:

1. A best-effort consumer now allows pruning only up to `LastCommittedBy(now − ReplayWindow)`. Its cursor only says where the forwarder resumes. `TestComputeBoundary` covers a best-effort cursor inside the window, and the boundary does not move. This also meets A1 decision D1-5.
2. Only a C6 `relp-tls` target may be required. `ConsumerID` is the C6 target name, and `Delivery` uses the C6 class strings.
3. `Read(after)` past a pruned range returns the first retained events, with no error.
4. The clock-step note is in section 3.

The new health type `store.mode-changed` (collecting, drain-only, blocked, failed) is fine. C4 lists it once the `store.*` names are final. The original outcome at 63308b3 was "accepted with changes".

## Re-check at 8c1eb82 (2026-10-24)

Still **accepted**. I read the changes since 2ef46a2 that touch the forwarder and intake: `outbox.go`, `class.go`, `layout.go`, `audit.go` and `commit.go`.

- **`ComputeBoundary` takes the stream class.** For audit, only required consumers count. This matches D1-15, under which C6 refuses any audit target other than a required `relp-tls` one. A best-effort audit consumer can therefore not arise from a valid C6 target, and if one did, C5 would ignore it.
- **Audit read-back as sealed C8 bytes.** C6 carries them unchanged in MSG and never re-renders them (C6 `doc.go`, audit rendering TODO(C8)). `ChainAnchor` gives the receiver the starting link after a prune, so the chain still verifies upstream.
- **`AlarmCode.HealthType`.** Every result is a valid C4 health type token: `intake.drop-counted`, `forward.unreachable`, `store.audit-full`, `store.<code>`, and `store.mode-changed` for a mode change. Mapping `required-consumer-stalled` to `forward.unreachable` is what C4's definition of that type means.
- **Stream classes on `NewLog`.** A Syslog intake Log declares `syslog-stream` or `syslog-datagram` per stream. This is consistent with C6, where intake is out of scope, and with the C4 `syslog-receive` collection method.
- **`quota-reached` per batch without stopping the Log.** The forwarder only reads, so this does not affect it.

One note, not blocking. C6 now gives "required" a precondition: a target may be required only after a commissioning check shows its collector acknowledges after a durable write (C6 `Target.DurableAck`, C6-A6-1, A6 V-S6). C5's `Required` prunes on that acknowledgement. It would help to cite C6's `durable_ack` beside `Required` in `outbox.go`, so a reader of C5 alone sees why the acknowledgement can be trusted.

## Original review at 63308b3

The outbox gives the forwarder what it needs: committed events only, in seq order, at-least-once, with cursors that cannot regress or run ahead. Change 1 is blocking: as written, a best-effort target's replay window can be pruned away before the replay. Changes 2 to 4 are wording.

## Changes

| # | Change | Why | Blocking |
| --- | --- | --- | --- |
| 1 | For a best-effort consumer, `ComputeBoundary` should allow pruning up to `LastCommittedBy(now − ReplayWindow)` only, and ignore its cursor. Today it allows `max(cursor, aged)`. | ADR-0004 item 5 says a target that cannot confirm delivery keeps a replay window, and C6 mode B re-sends that window on every reconnect. A best-effort cursor is only "position sent". With `max`, every event sent in the last T seconds becomes prunable at once. A forwarder that reconnects after a quota-pressure prune then has nothing to replay, and those events may never have reached the collector. With `aged` alone, the window is kept whatever was sent, and anything older is prunable, as item 6 says. The cursor still tells the forwarder where to resume. | yes |
| 2 | Say that only a C6 target with transport `relp-tls` may be a required consumer, instead of "an acknowledging transport". Say that the forwarder builds its `Consumer` values from validated C6 targets: `ConsumerID` is the C6 target `name`, and `Delivery` is the C6 `class`, using the same two strings. | Plain RELP acknowledges, but anyone on the path can forge its acknowledgements, so it is best-effort in C6 (A1 ruling, 2026-10-23). `Consumer.Validate` cannot see the transport, so the rule has to live in C6, and C5 should point there. | no |
| 3 | Say what `Outbox.Read(after)` returns when events after `after` have already been pruned. I assume the first retained events, with no error. Then the reader sees the jump from `after` to a higher seq and reports it. | A best-effort target that was down longer than its window loses events by design (ADR-0004 item 6), but the loss must be visible (P5). C6 reports the skipped range as a C4 `forward.unreachable` health event with `skipped_from` and `skipped_through`. That needs the jump to be observable, not an error the forwarder might retry forever. | no |
| 4 | Note that `CommittedAt` is wall-clock time, so a forward clock step (w32time correcting a drifted clock) makes `LastCommittedBy(now − window)` cover more events, and a best-effort window shrinks for that pass. | It affects only best-effort targets and errs toward pruning, not toward unbounded growth. But a reviewer should not have to work it out, and A6 may want a test that steps the clock. | no |

## Checked and agreed

- **Event identity.** `NodeID`, `StreamID`, `Key` and `Key.String` match C4 exactly, including the patterns. They become aliases once C4 merges. The store writes the assigned seq into the event's `id`, so `Stored.Event` passes C4 `Validate`, and `Stored.Key` equals its `id`. A producer checks with `ValidatePending` (seq 0) before commit (agreed with A5 at de3476e).
- **Evidence.** `native.evidence.ref` = `"sha256:" + evidence.sha256` is the capture name, enforced in C4. When an event is stored without `native.bytes`, the forwarder gets the record from `ReadCapture(EvidenceRef)` at `native.span` before rendering, and C6 renders exactly those bytes.
- **Mode A cursors.** A RELP window keeps several frames in flight. The forwarder saves a required target's cursor only up to the highest seq for which it holds a RELP `200 OK` for that seq and every seq before it. `SaveCursor` rejecting regress and ahead is what C6 needs.
- **Required consumers and quota.** A required target that stays down eventually fills the quota. Adapter evidence then stops collecting, with `collection-stopped`, and nothing unconfirmed is evicted. That is ADR-0004 item 6 as written. `required-consumer-stalled` maps to C4 `forward.unreachable`.
- **Syslog intake.** `refuse-new` for stream Syslog: nothing is acknowledged without a `Receipt`, so a RELP or TCP sender is pushed back. `drop-and-count` for UDP: the count is persisted and forwarded as C4 `intake.drop-counted`. Both match C4.
- **No consumer, no prune.** A stream with no consumers is never pruned. That matches V-S9. The node simply fills its quota.
- **`store.*` health types.** These are fine: C4 `Health.Type` is an open set. They should be listed in C4 once their names are fixed, so A6 can test against one list.
