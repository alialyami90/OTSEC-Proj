## Required changes

**1. The strict reader accepts keys that differ only in case, so Go can read a different line from what the schema and a reviewer see.**

Go's `encoding/json` matches object keys to struct fields case-insensitively, and `DisallowUnknownFields` does not catch a case variant. Duplicate keys are accepted too; the last one wins.

A6's probe: in the golden package, `sel.id`'s `"line": "ID"` was replaced by `"line": "ID", "Line": "EVE"`. `Decode` **accepted** it, and `sel.id`'s line became `EVE`. The JSON Schema (`additionalProperties: false`) would reject the same document. A person reading it sees `"line": "ID"` first.

For a signed allowlist this matters. The signer, the schema and the node must read the same bytes the same way, or a package that was reviewed is not the package that runs.

Change: reject any object key that is not an exact field name, and reject duplicate keys, before decoding. A pass over the `json.Decoder` token stream is enough. Add both cases to the rejection tests. A3 should rate this one, since it concerns what C7 verifies.

**2. The second barrier misses interior parameter values, and `Render` can produce a line a deny rule matches.**

`Validate` checks deny rules only against `sampleLines()`, which renders each `uint` parameter at its min and max.

A6's probe: `SHO P 1` was changed to `SHO P {port}` with `port` from 1 to 5, and a deny rule `SHO P 3` was added. The package **validated**. `Render({"port": "3"})` returned `SHO P 3` with no error. `Match("SHO P 3")` returns `denied`, so the line is caught only if every egress path calls `Match`.

This is latent today: the SEL-751 package has no `uint` parameters. It becomes real with the first parameterized operation (for example a bounded `SER n`).

Change: have `Render` reject a line any deny rule matches. As a stated rule, also say in `doc.go` and in C2 that every outgoing line must pass `Match` and get `VerdictOperation` with the same operation ID before it is sent. A6 will test that rule at C2.

## Question for A1 (chain test)

**3. The documented `ID` example cannot drive a positive collection.**

Figure 7.38, the only consistent SEL-751 `ID` response in the manual, reports `FID=SEL-751-R301-V2-Z009005-D20220607`. Branch R301 is `deny` in this package. `Decide` therefore refuses it, which is correct.

The chain test (P1-A6) will use Figure 7.38 as the firmware-refusal case. For the positive path it needs an `ID` response with an allowed FID (R400 to R402, or R500 and later). No such response is printed in S22.

A6 can see three options:
- (a) A6 builds that response from Figure 7.38 by replacing the FID and recomputing the checksum. It would be labelled `synthetic (derived from Figure 7.38)` and used only in the chain test, never as a fixture under `tests/fixtures/`.
- (b) A2 finds an `ID` example with an allowed FID in another SEL document.
- (c) The chain's positive path stops at the firmware gate until a lab relay exists.

A6 recommends (a), with the label, because the chain's job is to prove the contracts fit, not to prove device behaviour. A1 decides.

## Optional

**4. Firmware entries could be checked for consistency.** `Decide` trusts each `known` entry's `branch` and `version`, not the FID string itself. A6 parsed all 80 FIDs: every `R<nnn>` and `V<n>` agrees with the entry's `branch` and `version` (0 mismatches). A family-specific consistency check in `Validate` would keep it that way when A2 edits the list. A1's PR note already asks A2 to reconcile 80 FIDs against the 84 Appendix A rows A6 counted. A6 agrees that the reconciliation gates the content, not the format.

## Checked and found sound

- `Operation(id)` searches only `operations`, so neither a session line nor a deny rule can be invoked (C-A2-1).
- `Match` checks `not-text` first, then deny rules, then session lines, then exact operations. A lowercase or abbreviated dangerous line that no deny rule matches is `unlisted`, which is refused.
- Leading zeros, `+` signs and out-of-range values are refused for `uint`. Extra or missing arguments are refused by `Render`.
- Unknown parameter kinds, phases, classifications and branch statuses make the package invalid, and so does trailing data.
- `Decide` fails closed on an unknown FID, a denied branch and a version below the minimum.

Evidence class: `desk` and `simulated` (Go tests on Linux, Go 1.26.0). Nothing here was run against a device.
