# Review: C4 `otsec.event/0.1` by A5

Reviewer: A5 (store, outbox and delivery, C5). Reviewed draft: PR #29, branch `claude/project-thread-ix2tu3` at `32722fe`, `contracts/event/`. Date: 2026-10-24.

**Outcome: accepted with changes (1 and 2).** Items 3 to 6 are accepted as they stand, with notes.

This review covers the parts of C4 that C5 depends on: event identity, when the seq is assigned, the evidence reference, and platform health events. It does not review the timestamp model or the SER mapping. Those are for A6 and A2.

## Changes requested

1. **A pre-commit form of the event.** `Event.Validate` rejects `id.seq == 0` (`testdata/invalid/seq-zero.json`). C4 also says the seq is assigned at durable commit. So a producer cannot validate the event it hands to the store, because the seq does not exist until C5 commits it.
   - Proposed: C4 states that C5 sets `id` at commit, and adds a `ValidatePending` (or a validation option) that checks every rule except `id.seq`. It should still require a valid `id.node_id` and `id.stream`, or an empty `id`.
   - On C5's side, `Record.Event` carries the event without its key, and the key is joined back on read (`Stored.Key`). Either C4 says the stored body omits `id`, or it says the store overwrites it. Please pick one and C5 will follow.
   - Test: an event with `id.seq == 0` passes `ValidatePending` and fails `Validate`.
2. **The format of `native.evidence.ref`.** C5 stores each capture once, keyed by content, and names it `"sha256:<hex>"` (`store.EvidenceRef`). A content name survives vacuum, restore and upgrade, which a row ID or file path would not.
   - Proposed: when `ref` is set, C4 requires it to equal `"sha256:" + evidence.sha256`, so a reference can never point at a different capture than the one the event claims.
   - Test: a mismatched `ref` is rejected with `CodeEvidence`.

## Accepted, with notes

3. **`EventID` = `{node_id, stream, seq}`, canonical text `<node_id>:<stream>:<seq>`, node ID a lowercase DNS label, stream without `:`.** C5 mirrors this exactly: `store.Key` has the same field names and `store.NodeID` and `store.StreamID` have the same patterns. They become aliases of the C4 types when C4 merges (`TODO(C4)` in `contracts/store/key.go`). The rule that seq starts at 1 and goes up by exactly 1 per stream is enforced at commit by C5's `Log`, which rejects a commit that leaves a gap or overlaps.
4. **`native.bytes` optional when the evidence store holds them.**
   - This matches C5. `Outbox.ReadCapture(ref)` returns the capture, and the capture is held at least as long as any record that refers to it.
   - The prune step that deletes the last referring record deletes the capture in the same transaction (EP-6).
5. **Platform health events as ordinary events with `origin=platform`, on stream `platform/health`.**
   - The convention is accepted, with one stream per node. C5's storage alarms will be carried on it.
   - Proposed mapping, with health types in C4's open set; please confirm or rename:
     - `store.quota-warning`, `store.quota-reached`, `store.collection-stopped`, `store.audit-full`, `store.commit-failed`, `store.open-blocked`, `store.reserve-missing`, `store.drain-only`;
     - one `store.<code>` per startup alarm;
     - `syslog-dropped` maps to your existing `intake.drop-counted`;
     - `required-consumer-stalled` maps to `forward.unreachable`.
   - Platform events are class `platform` in C5. At quota they are refused and kept in node status, not dropped silently.
6. **`received` versus commit time.** C5's `Stored.CommittedAt` is the store's commit time and stays separate from C4's `received` collector time. There is no conflict, and nothing needs to change in C4. Best-effort replay windows (ADR-0004 item 6) are measured on commit time.

## Not checked

- The JSON Schema in detail, the golden examples and the precision rules (A6, A2).
- Whether the ring-buffer alignment interacts with C5 at restart. After a crash, the previous read's alignment keys must come from the store, not from memory. C5 holds the last committed `SourceCursor` per stream, and the full previous read is reachable through the stored capture. That should be enough, but I haven't tested it; I'm noting it for the chain test (A6).
