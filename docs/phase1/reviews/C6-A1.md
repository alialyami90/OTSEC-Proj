# C6 `otsec.syslog/0.1`: A1 review

- **Reviewed:** PR #42 at `8f96a40` (`contracts/syslog/`, plus the C4 additions for D1-16 and D1-17), by A4.
- **Reviewer:** A1, as integration and contract owner, 2026-10-24.
- **Outcome:** **accepted.** Notes 1 to 3 should be made before 1.0. None of them blocks the merge.

## Method

- Read `doc.go`, `target.go`, `render.go` and `relp.go`.
- Ran `go vet ./...`, `gofmt -l contracts` and `go test ./contracts/...` on the PR head. All were clean.
- Probed `ParseRELPResponse` with 13 inputs from a test file of A1's own, outside A4's tests. The file was removed afterwards and is not in the PR.
  - **Accepted:** `1 rsp 6 200 OK\n` (an acknowledgement), `0 serverclose 0\n`, and an rsp whose data has a status line followed by offers.
  - **Rejected:**
    - `200` with no `OK`, and `200 OKAY`;
    - a leading zero in TXNR or in DATALEN;
    - `RSP` in upper case, and a double space;
    - a CR before the LF;
    - a serverclose with a TXNR other than 0;
    - a DATALEN above 4096.
  - **Incomplete:** a frame with no final LF returns `ErrIncomplete`, never a partial acknowledgement.

## Agreed

- **Required class:** only RELP over TLS may be `required`, so a forged or lost acknowledgement can never advance pruning.
- **Mode B:** the replay window matches C5's consumer window, as D1-5 requires.
- **D1-15:** audit goes only to required `relp-tls` targets in RFC 5424 with room for a whole sealed record, and `Target.Validate` refuses anything else. The invalid examples cover UDP, plain TLS and a target too small for a record.
- **D1-13:** `v` and `ev` let a receiver tell a version it cannot read from a malformed event.
- **Device content cannot forge structure (AP-20):**
  - every SD-PARAM value passes `printable`, or travels as `<name>_b64`;
  - native bytes travel only in `dtext` or `dtext_b64`;
  - MSG carries only fixed tokens and values matching `summaryToken`;
  - a rendered message cannot contain LF, CR or NUL.
- **Size handling is visible, never silent:**
  - the device text is dropped first, then the summary;
  - each step is reported in `Outcome` and as a `forward.text-omitted` event;
  - a message that still does not fit fails with `too-large`, and the cursor passes it only after the `forward.too-large` health event has been accepted.
- **The C4 additions:** `time.node-stepped` (D1-16) and the residual repeated-key case in `doc.go` (D1-17) match the decisions.

## Notes

**1. An acknowledgement must count once.**
- `ParseRELPResponse` relies on `outstanding(txnr)`.
- The contract should state that a transaction stops being outstanding when its first response is parsed. Then a repeated `200 OK` for the same TXNR is a violation, not a second advance.
- Add a test with two responses for one TXNR.

**2. Audit targets should authenticate the node.**
- With `audit` set, require `tls.client_credential_ref`, so the collector can refuse an audit stream that is not from an enrolled node.
- The C8 chain shows tampering after the fact. Mutual TLS also stops an impostor from writing audit records at the collector at all.
- A3 to rate.

**3. Bound the caller's buffer.**
- `ErrIncomplete` asks the caller to read more. Export the largest legal frame as `MaxRELPFrameLen`: 9 + 1 + 11 + 1 + 4 + 1 + 4096 + 1 octets.
- State that a buffer that reaches it without a complete frame is a violation, so a collector that never sends LF cannot make the node buffer without limit.

- A1 wrote the probes. They are not A4's tests.
- Evidence class: `desk` (Go on Linux). No collector was contacted.
