## Outcome: accepted with changes

| # | Change | Why | Blocking |
| --- | --- | --- | --- |
| 1 | **A level-0 operation carries no credential.** `ValidateWith` refuses an invocation whose operation is at level `0` and that names a `credential_ref`, with `refused.limits`. Add the test next to "Level 0 operation with no credential". | C7's IPC already says that a level-0 run carries no `credential_ref` (C7-A2-5). Today `sel.id` with a credential passes `ValidateWith`, so C2 would accept an invocation that C7 cannot produce. The two contracts must refuse the same set. Resolving a credential the operation does not need also widens the window in which the secret is in the collector's memory (A3 credential design, section 10). | yes |
| 2 | **The operation must be one the profile names.** `CheckAgainst` refuses an `operation_id` that no `adapter-operation` capability in the profile lists, with `refused.not_invocable`. | The register lookup proves the operation exists in the register the collector loaded. The profile is what ties that register to this asset's family. Without the check, an invocation built against the wrong family's register, or an operation the capability matrix does not claim, passes both checks. It is one loop, and it closes the C1–C3 link the chain test exercises. | yes |
| 3 | **Address-only refusal code and message.** An address-only binding is refused because the expected identity count differs, which reports `refused.limits` with a message about attribute counts. State it directly ("binding compares nothing; no C2 session runs on it") before the count check, so the audit record names the real reason. The code can stay `refused.limits`. | Operators read these in C8 audit records. | no |
| 4 | **Order of checks.** In `CheckAgainst`, check that `asset_id` matches before reading the asset's suspension or binding, so a mismatched asset is never reported as suspended or credential-unavailable. | The first failure is the one recorded. | no |

## Checked and fine

- Strict decoding through `strictjson.Decode` (D1-10). Invocations are never received from the main process; the collector builds them from an accepted C7 run.
- `RegisterLookup` refuses session-control lines, deny rules and unknown IDs (C-A2-1), using the merged SEL-751 register.
- The limits ceilings, and `MaxConcurrentSessions` of 1 matching D1-18.
- The STX/ETX framing rule: kept in the transcript, excluded from every span. The assumption that the prompt follows ETX is marked as an assumption, and H-12/H-13 test it.
- The C7 credential reference syntax copy, kept equal by `TestCredentialRefMatchesC7`. The same pattern is used for `node.ID` and `MaxAlignRows`.
