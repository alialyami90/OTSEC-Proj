## Outcome: changes required

The probe grammar holds against every hostile and near-miss input A6 tried. The code taxonomy and the suspension tables match C1 and C7. The framing rule (STX and ETX kept, never inside a span) holds.

The session rules are weaker than `doc.go` says. "No line is sent before a prompt" is checked only in the probe phase. As a result, a result validates when the password went out with no `Password: ?` before it (C-17), or when `QUI` followed the password with no Level 1 prompt (C-19). These are the two failures the SEL-751 profile shows are unsafe. A credential can also be sent with no language probe and no identity check before it. Required changes 1 to 3 fix these. Change 4 is A1's change 1, confirmed by probe.

## Required

**1. Check every send against the prompt before it.** `doc.go` says no line is sent before a prompt, but `check.probe` checks only the probe phase. `session` takes `password_prompt` and `quit_sent` on trust. Change: walk every sent segment except the wake, and take the received bytes since the previous send, with framing stripped.
   - Probe lines and `ACC` need `=`.
   - The credential needs `Password: ?`, and `password_prompt` must equal that test.
   - The first send after the credential needs a Level 1 prompt (`=>`), or `=>>` for `failed.unexpected_access_level`. Today only `failed.auth_rejected` forbids a send after the credential. P2 shows that `failed.timeout` and `failed.transport_closed` must forbid it too.
   - Operate lines need `=>`.
   - A prompt counts only at the start of a line: after CR, LF, ETX or the start of the received bytes. Without this, P5 passes.

   This one check closes P1 to P5. It is the result-side half of C-17 and C-19, and A6's V-S13 cases depend on the result telling the truth.

**2. No auth phase without an accepted language probe.** P6 sends `ACC` and the password with `language_probe` not-run, and `Validate` accepts it as ok. ADR-0005 requires the `QUI` probe before `ACC`. `language_probe` may be not-run for "a profile without a probe", but the result does not say which profile it ran under. For 0.1, where SEL-751 is the only profile that sends `ACC`, make a sent auth-phase segment require `accepted`. Otherwise, carry the profile ID in the result.

**3. The identity check must precede the credential.** P7 compares the FID only in the operate phase, after the password, and validates as a match. `doc.go` and C1 say the FID is checked at Level 0, before any credential (AP-27). Change: when `credential_sent` is true, at least one identity item must point into received bytes before the first sent auth-phase segment. Better still, mark which items are pre-credential, so the serial number from the SER header can stay a later check.

**4. A level-0 operation carries no credential (P8).** This is A1's change 1. A6 confirms it by probe.

## Should

**5. `quit_sent` must be the bytes (P9).** A sent close-phase segment counts as `QUI` whatever it holds. Change: every close-phase send must be exactly the `QUI` line.

**6. `access_level` must match the prompts (P11, P12).** Nothing ties `access_level` to the received prompts. `refused.session_elevated` passes with only `=` received. Change: `access_level` is the highest prompt received. `session_elevated` needs the first received prompt to be `=>` or `=>>`.

**7. A session that reached Level 1 ends with `QUI` (P10).** After Level 1, `failed.timeout`, `failed.response_too_large` and `failed.egress_violation` may end the session without `QUI`. A session that ends without `QUI` stays at Level 1 until TIDLE (p. 7.16), and V-S13 requires every session to end with `QUI`. Change: when the last prompt was `=>` and the transport is still open, require `QUI`. Where the code needs an exception, say why in `doc.go`, as `language_not_english` does. `failed.transport_closed` stays exempt.

**8. Say what a timeout after the password suspends.** `failed.timeout` and `failed.transport_closed` after the credential, with no Level 1 prompt, suspend neither the asset nor the credential. The relay may be sitting in `Password: ?`, or it may have counted a failure. Whether failures count across connections is H-15 (a) and H-04. The C7 failed-auth floor (D1-20) already holds the next attempt back for 31 minutes, so this is not a lockout risk today. Change: either suspend the credential for these cases, as for `auth_rejected`, or state in `codes.go` that the floor alone covers them.

**9. Decode 0.1 results strictly (P13).** D1-10 allows `Forward` for C2 results. C1 and C4 still use `Decode` for their own minor and `Forward` only for later ones, so a writer bug in 0.1 is caught. Change: do the same, or say in `doc.go` why results differ.

**10. Citations.** H-12 is the Spanish-port probe. The QUIT reply, the framing and the prompt position are H-13. Change H-12 to H-13 in `probe.go` (twice), `doc.go` and `adapter_test.go`. The session state left after a wrong password or without `QUIT` is H-15.

**11. `refused.limits_out_of_range` for an invocation that names another asset.** `CheckAgainst` reports an asset, endpoint, profile or expected-identity mismatch with this code. The code's comment says "malformed invocation or limits above the ceilings". Change: widen the comment, or add `refused.invocation_mismatch`. On the order of checks, A6 agrees with A1's change 4.

## Limits ceilings: confirmed

A6 checked each ceiling against V-S13, the SEL-751 capability profile and the manual citations it carries. Each is an outer bound: the profile's `session_limits` bind, and `CheckAgainst` enforces them.

| Ceiling | Value | A6 |
| --- | --- | --- |
| `MaxConcurrentSessions` | 1 | Confirmed. V-S13 requires a peak of at most 1 session per device. Port 1 has two Telnet sessions (Table 7.5 note a), so an engineer keeps one. Whether a collector session blocks an engineer is H-03. |
| `MinMinIntervalMS` | 1,000 | Confirmed as a floor only. The SEL-751 profile sets 60,000 ms, a platform choice. V-S13 checks the poll rate against the profile, not this floor. |
| `MaxConnectRetries` | 2 | Confirmed, on the condition the comment states: retries happen only before any byte is sent, so a retry is never a second session or a second password. |
| `MaxConnectTimeoutMS` | 30,000 | Confirmed. |
| `MaxStepTimeoutMS` | 60,000 | Confirmed for Telnet. A full 1,024-row SER over serial at 9,600 baud is about 85 KB, roughly 90 s as one step, so a serial endpoint would hit this ceiling. Revisit when serial is in scope. The slice is Telnet only. |
| `MaxDeadlineMS` | 600,000 | Confirmed. A stuck session holds one of the two Telnet sessions for at most 10 minutes. |
| `MaxResponseBytes` | 1 MiB | Confirmed: 1,024 rows (Table 7.63) at about 80 bytes each is under 100 KiB. The 80-byte row length is `inferred` from the Figure 10.16 layout, not measured. |

### Required

**12. `QUI` after a timeout that followed `ACC`.** In P15, `ACC` is sent, `ACC` CRLF is received with no prompt, and `failed.timeout` follows. `QUI` is then sent in the close phase, and the result validates. The step-timeout exception in `dialogue` allows `QUI` with no prompt whenever no credential was sent. After `ACC`, though, the relay may still print `Password: ?` (p. 7.33). `QUI` would then be read as a password attempt. No D1-20 floor was started, because no password was sent. So the next session, 60 s later, can add a second attempt if the relay keeps that state across connections (H-15 (a)).

Change: the exception applies only when a level prompt was received after the last `ACC`. With no `ACC` sent, it applies as today. `failed.response_too_large` takes the same rule. A6's P16 is a timeout at `Password: ?` before the credential, and it is already refused.

### Should

**13. `QUI` after a rejected probe.** In P17, the `QUI` probe reply is off-grammar but still ends in `=`, as `Comando no valido` CRLF `=` does. `refused.language_probe_rejected` then sends `QUI` in the close phase, and the result validates. D16, and `doc.go` for `language_not_english`, say that once the port is not known to be English, nothing more is sent. Change: with a rejected probe, the close phase is empty.

### Note

A timeout during the probe can only be reported as `refused.language_probe_rejected`, which suspends the asset with `language-not-english`. Two reasons force this:
- a `QUI` probe with no reply cannot be `accepted`;
- `rejected` requires that code.

This fails closed and A6 accepts it. `doc.go` should still say so, so that an operator who sees a network fault suspended as a language fault knows why.

### Should, not blocking

**14. After an unanswered `ACC`, nothing starts the floor.** The new comment in `dialogue` says "the C7 floor covers the next session". C7 (`authz` doc, D1-20) starts the floor when the password is sent, not when `ACC` is sent. After an unanswered `ACC`, no password was sent, so no floor runs.

If the relay later prints `Password: ?` and keeps that state across connections, the next session 60 s later has two possible outcomes:
- if the relay shows the prompt on connect, the session is refused with `session_pending_password`, which is safe;
- if the relay is silent on connect, the session sends the wake into it, and the wake is a password attempt. Three such sessions would pulse SALARM.

Both of these depend on H-15 (a).

Change (A3 with A2): an authentication is unconfirmed from `ACC` until a level prompt, not from the password. This also covers `password_prompt_absent`, because `=>` then confirms it at once. Until that change is made, correct the comment.
