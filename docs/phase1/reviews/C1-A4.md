# Review of C1 `otsec.asset/0.1` by A4

- Contract: C1, `contracts/asset/`, PR #32, commit 94afea2. Owner: A2.
- Reviewer: A4 (telemetry), as a consumer: C4 events reference assets, and the Syslog receive path must map a sender to an asset.
- Date: 2026-10-24.
- Scope: the asset ID, the node ID, endpoints of the Syslog transports, and the identity binding as it applies to received Syslog. I did not review the capability profiles, posture labels or attribute confidence rules beyond what events need.
- Method: I read `doc.go`, `asset.go`, the RTAC examples (`valid/sel-rtac-syslog.json`, `valid/profile-sel-rtac-syslog.json`) and `A2-contracts.md`, and checked each point against C4 at 32722fe (PR #29) and ADR-0004.

## Outcome: accepted with changes

C4 can reference a C1 asset by its ID without defining one of its own, and the sender-to-asset mapping for Syslog is expressible with Syslog endpoints. Change 1 avoids an import cycle that the current TODOs would create. Change 2 is needed so the receive path maps senders the same way on every node. Changes 3 and 4 are wording. None is a safety objection.

## Checked and agreed

- **Asset ID.** A lowercase RFC 9562 UUID, assigned and never derived from device content, checked by the exported `ValidAssetID`. C4's `AssetRef.ID` and `Sender.AssetID` will use it: C4 carries the ID and nothing else from the asset, and the binding method and confidence stay in C4 because they describe how one event was attributed, not the asset. C4's examples currently use `sel751-feeder1`; I am switching them to UUIDs on PR #29.
- **Node ID.** C1's pattern is identical to C4's `NodeID` (`^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$`).
- **Binding terms line up.** C1 `address-only` (spoofable) is what C4 records as `sender-address` with `origin_auth: none` for UDP and TCP. C4's `configured` means an operator configured the mapping, not that the device was authenticated, which matches C1 labelling the binding spoofable.
- **Content-based attribution stays possible.** When no endpoint matches, a hostname in the message can be compared with C1's `hostname` attribute; C4 records that as `content-field` and never as `configured`.
- **Plaintext labels.** `syslog-udp` and `syslog-tcp` are forced to `plaintext-unauthenticated` with an acknowledgement. That agrees with C6, which labels plain TCP and UDP insecure on the forwarding side.
- **Times.** `observed_at`, `since` and `at` use RFC 3339 UTC with Z, the same textual rule as C4's platform times. C4 exports no time type, so there is nothing to import.

## Left out of C1, and fine for 0.1

- Windows host events (C4 kind `host-event`, collection `host-push`) from the SEL-3355-2 and the zenon HMI are attributed by computer name. C1 can express that only through the `hostname` attribute; no endpoint transport describes it. That is enough until the host collection contract exists.
- A `syslog-tls` sender identified by its client certificate would be `pinned-key`. No slice-1 device does it.
