## Required changes

**1. A credential's access level cannot be checked against anything, and `2AC` is accepted.**

`CredentialRef.AccessLevel` is a device-native name such as `ACC`. The doc and the design say the collector checks it against "the family ceiling in the register", and that "no credential for Level 2 or above can be installed with purpose `collect-readonly`" (design section 5). C3 has no ceiling. Its operations carry numeric levels (`0`, `1`), and its session lines carry `0 -> 1`. Nothing maps `ACC` to a level. A6's probe: a reference with `access_level: "2AC"` validates.

The egress gate still holds. `Permit(auth, "2AC")` is denied, so the transport would send `ACC` and then whichever password was installed. But the record would then say Level 2 for a credential used at Level 1. Alternatively, an admin could install the Level 2 password under the label `ACC`, and nothing would notice. Least privilege (principle 4) depends on the level the password actually opens, and the contract cannot check that.

Change:
- Define the check in the contract. `access_level` must equal the `line` of a session-control entry in the verified register that runs in the `auth` phase. For SEL-751, that is only `ACC`. The collector applies the check at install and at every run.
- Add `2AC` as an invalid example.
- State in the design that the platform cannot tell a Level 2 password typed in as `ACC`. It is caught only if the relay rejects it at `ACC`, which is an H-15 item.

**2. The credential slot must open once per session, and the session must end with `QUI` whenever `ACC` succeeded.** (Design; contract doc text.)

A2's C7 review found two manual facts:
- After a wrong password, the relay asks `Password: ?` again, up to three times (S22 p. 7.33). Design section 5 opens the slot "right after the documented `Password: ?` prompt that follows `ACC`". A second prompt also follows `ACC`. Read literally, the rule allows a second send. It must be read as `auth-failed`.
- A Telnet session closed without `QUIT` stays elevated until `TIDLE` expires (S22 p. 7.16). Section 5 disconnects without `QUI` only after a wrong password, when the session is not elevated. But the identity-mismatch path and any error or timeout after a successful `ACC` also close the session. The design does not say they send `QUI`. A2 treats it as possible that a new connection inherits the elevated state.

Change:
- **Slot:** the slot opens at most once per session. A second `Password: ?` is `auth-failed`: send nothing, disconnect, suspend.
- **Close:** after a successful `ACC`, every exit path sends `QUI` before the TCP close, including identity mismatch, a parse failure and a timeout. A failed send is recorded on the session-close audit record.
- **Tests:** add T-10 (a second prompt gets no second secret) and T-11 (`QUI` on each exit path after `ACC`). A6 will build both into the recording simulator, labelled `documented-example` from S22, together with the persisted elevated state A2 asked for. H-15 will capture the real behaviour on a lab relay.

## Should

**3. The secret check leaves the register test to the caller, and the likely wiring lets command words through.** `ValidateSecret` takes `isRegisterLine` as a function. A6 wired it the way an implementer most likely would, as "anything `Matcher.Match` does not call unlisted". It then ran candidate SEL-751 passwords (maximum 12 characters):

| Secret | `Match` | Accepted as a secret |
| --- | --- | --- |
| `OPEN`, `open1234`, `Trip1`, `tri`, `set`, `pas`, `2ac` | denied | no |
| `QUI`, `SHO G` | session or operation | no |
| `qui`, `quiet123`, `acc`, `accent12`, `ser`, `serial99`, `id`, `idle4now`, `sho g`, `show1234` | unlisted | **yes** |
| `close!` | unlisted, because `CLO\w*` stops at `!` | **yes** |

Approved lines are exact-case, so their lowercase and longer forms are unlisted. The deny rules assume that a command word ends at a space or the end of the line. The prompt-gated slot is the real barrier, and none of these is a write. But the check exists so that the slot "can never carry a command", and it does not achieve that.

Change: put the check in the contract, not in the caller. A function over the verified `Matcher` should reject a secret if its upper-case form starts with the mnemonic of any operation, session line or deny rule in the register. That is the first three characters for SEL. Or the family's register entry can give the rule.

**4. The identifier patterns are provisional, and the examples break C1.** `asset_id` accepts any dotted token. C1 requires assigned lowercase UUIDs, and the golden run uses `site-a.relay.feeder-3`, which C1 rejects. `node_id` accepts upper case, while C4 requires a lowercase DNS label. Today this fails closed, because a mismatch only refuses. Change: import C4's node ID now that #29 is merging, and C1's asset ID when #32 merges, then fix the examples.

**5. The failed-auth floor must survive a collector restart.** The floor is the only limit on alarm cycling by a compromised node service (design section 5). If it is held in memory, a restart of the collector resets it. Change: persist the time of the last failed authentication per asset in the credential store, and take the floor from it. Add T-9b: fail once, restart the collector, ask again inside 15 minutes, and expect `rate_limited`.

**6. The post-login identity check only covers SER runs.** The serial number comes from the SER report header (design section 5, C1-A3-5). A run of `sel.settings.show_global` or `show_port1` authenticates, but nothing after login checks that it reached the bound device. Change: say which operation supplies the serial on a non-SER run, or run it in every authenticated session.

**7. Revoking a release key does not say what happens to a package already active.** `VerifyRegisterPackage` refuses a revoked key at verification time. Nothing says that a package already active and signed by that key is re-verified. Change: on any change to the trust anchors, the collector re-verifies its active packages, and drops any that no longer verify. Collection for that family stops, and an alarm is raised (SC-18).

## Checked and found sound

- **Strict decoding.** These are refused:
  - `"Run"`;
  - a Kelvin-sign `Kind`;
  - a duplicate parameter;
  - a non-integer, negative or 2^64 `policy_version`;
  - a UTF-8 byte-order mark;
  - 8,193 bytes (8,192 are accepted).

  A JSON escape that decodes to a real key or value is read as that key or value, which is correct. A `null` second body beside `run` is accepted, which is harmless because it is nil.
- **Principals.** A `run` on behalf of a human or the system is refused with `principal_not_permitted`.
- **`ValidateAgainst`** on the merged SEL-751 register:
  - accepts `sel.ser.read_all`, `sel.id` and `sel.settings.show_port1`;
  - refuses `sel.session.acc` and `sel.session.qui` (as `unknown_operation`, which is acceptable);
  - refuses an undeclared parameter on `SER` (`bad_params`);
  - refuses a nil matcher (`register_unverified`).
- **The 20 invalid request examples** each give exactly the refusal code their file names. The 4 valid ones decode.
- **`SealAAD`** binds the reference, version, asset, node, transport and access level. Each field is newline-delimited, and none of them can contain a newline.
- **Register package verification:**
  - Ed25519 only;
  - one anchor per key ID;
  - an active key of the right size;
  - the payload size is bounded before parsing;
  - the signature is checked over the domain-separated input before the payload is parsed;
  - anti-rollback, with an equal revision accepted only with identical bytes.

## Credential design (B-04)

The design meets what B-04 asked for:
- the secret is held only by the collector account;
- the binding is checked at use;
- the plaintext and scope labels are carried;
- the platform never writes to a device;
- suspension and revocation are audited;
- the residuals are stated (section 9).

The reuse rule (section 6) keeps a lab Telnet password from becoming a production one.

Changes:
- **D-1:** change 2 above, the single-use slot and `QUI` on every exit.
- **D-2:** change 1 above, a checkable access level, plus the sentence on a Level 2 password typed as `ACC`.

A6 also adds to section 10:
- T-9b (change 5);
- T-10 and T-11 (change 2);
- T-12, an install whose fingerprint does not match the commissioning record. The Phase 2 client refuses to seal.

T-1 to T-5 need the Windows site image, and they stay with H-14. In particular, whether a virtual account's SID can go on a Platform Crypto Provider key ACL (T-2) is `[inferred]`.

**New, should (not blocking):**
- **The secret policy still comes from the caller.** `doc.go` says the family's register entry supplies `MaxLen`, `Allowed` and `MnemonicLen`, but the register has no such fields yet. A caller that leaves `MnemonicLen` at 0 gets whole-word mode, where `quiet123`, `close!` and `serial99` pass again. A zero `SecretPolicy` also accepts. Change either of these:
  - add the policy to the register package (or name an `authz` value for SEL-751) so the collector never builds it itself;
  - or make whole-word mode an explicit setting, so that 0 is not the permissive default.
- **`Allowed` is matched unanchored.** With a family pattern such as `[A-Za-z0-9]+`, `Otter #26` passes, because the pattern matches part of it. The SEL-751 pattern in A3's test is anchored, so this needs a careless register entry. Match the whole secret (`^(?:…)$`) in `ValidateSecret`.

## Follow-up at e0821a6 (2026-10-24)

A3 fixed both new should items in `3887402`. A6 probed them at `e0821a6`, where CI is green.

- **Policy from the caller.** `authz.SecretPolicies["sel-751"]` names the SEL-751 policy: `[!-~]`, 1 to 12, mnemonic length 3. A policy must set exactly one of `MnemonicLen` and `WholeWord`, so a zero policy, a policy with neither set, and a policy with both set are all refused. Whole-word mode now has to be chosen explicitly, and in that mode `quiet123` and `close!` pass, as intended. The policy is meant to move to the C1 profile (D1-18).
- **Anchoring.** `Allowed` is matched as `^(?:…)$`. `Otter #26` is refused under both `[A-Za-z0-9]+` and `a|[!-~]+`, so wrapping a pattern that contains an alternation does not let it through.

Nothing is left open on C7.
