# C8 `otsec.audit/0.1`: A6 review

- **Reviewed:** PR #38 at `6142ed0` (`contracts/audit/`), A3.
- **Reviewer:** A6, 2026-10-24.
- **Outcome:** **accepted.** Changes 1 and 2 should be made, and neither blocks merge.

A6 drove `ParseRecord`, `ValidatePending` and `VerifyChain` from a test outside the package, without A3's helpers. The input was A3's 6-record chain (`testdata/chain/slice-session.jsonl`), changed one way at a time.

## Tamper tests on the chain

| --- | --- |
| None, without a head and with a head | passes |
| Record 3 dropped | broken |

| Record 3 re-encoded with a leading space (same JSON) | broken at the next record |

The chain detects every change that has a later record after it, and a tail change only against a checkpoint held outside the node. That is what `doc.go` claims.

## Record parsing

| Probe | `ParseRecord` | `ValidatePending` |
| --- | --- | --- |
| `Password`, `pwd` nested in `actor`, `ſecret` (long s) | rejected at any depth | rejected |
| `SEQ` beside `seq`, duplicate `seq` | rejected | rejected |
| `api_token` or `secret_value` added | **accepted** | rejected |

All 5 invalid examples are rejected for their stated reason, and the valid one parses.

## Should

**1. `VerifyChain` does not bind a node unless a checkpoint does.** With no `from`, the node is taken from the first record, so a whole chain from another node verifies. A `from` checkpoint with an empty node ID is accepted. The probe removed 2 records and passed `from` with no node ID, and the rest verified. Change: give `VerifyChain` the node it expects, or refuse a checkpoint with no node ID. The verifier then never takes the node from the data it is checking.

**2. A 0.1 record with an unknown field passes `ParseRecord`.** `ParseRecord` uses `strictjson.Forward` for every minor. So a 0.1 record carrying `api_token` or `secret_value` parses, because only the listed names are refused. The normal path cannot produce such a record: `ValidatePending` uses `Decode`, and `Seal` re-encodes from the record's fields. But `ParseRecord` is also what reads forwarded and exported records. Change: as C4 does, use `Decode` for records stamped 0.1 or earlier, and `Forward` only for a later minor.

## Checked and found sound

- **`Seal` output passes `ParseRecord`.** A pending record that carries `seq` or `prev_hash` is refused.
- **Seq 1, the genesis `prev_hash` and `audit.chain.start` go together**, as the invalid example shows.
- **Telnet labelled anything but `plaintext-unauthenticated` is refused**, and so is a `denied` outcome without a reason code.
- **The forbidden-name check** is case-insensitive under Unicode folding, so `ſecret` is caught.
