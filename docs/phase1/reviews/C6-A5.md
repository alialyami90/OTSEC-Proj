## Should

**C6-A5-3. Where mode B resumes after a reconnect.** `doc.go` says the forwarder "re-sends the events committed in the last replay_seconds". Taken literally, a target that was away for longer than its window resumes at the start of the window. That skips events that were never sent but are still in the store, because nothing forced a prune. Proposed: resume from the lower of the cursor plus 1 and the first seq committed inside the window. If `Outbox.Read` then returns a jump, because events were pruned (C5 returns the first retained events with no error), report the skipped range as `forward.unreachable`, as A4's C5 change 3 intended. Mode A already resumes at the cursor plus 1. The same jump rule covers a plain RELP target that was away past its window.

**C6-A5-4. Target lifecycle and cursors.** The consumer ID is the target name, so:

- **A rename is a removal plus an addition.** The new name starts with no cursor. That is safe, because it holds everything back, but it replays everything retained. Say so, so that an admin does not rename a target to "tidy up" a busy node.
- **A new target needs a defined start.** Proposed:
  - The default is the first retained event (no cursor).
  - "Start from now", saving the cursor at the last committed seq, is an explicit admin choice, recorded in the `policy.apply` record.
  - A new required target on a store near its quota can stall the node into `store-quota-reached` while it catches up. The alarm C6-A3-7 already raises for target changes should also name the backlog.
- **Removing a required target** makes what it held back prunable at the next boundary computation. C6-A3-7's alarm should also say how many events that frees for pruning. C5 needs no change: a persisted cursor of a consumer that is no longer passed to `ComputeBoundary` is ignored.

## Notes, no change needed

5. **too-large depends on a committed health event.** The target's cursor passes a too-large event only after the `forward.too-large` health event has been accepted. That health event has to be committed to `platform/health` first. At the platform quota (`refuse-new`) it cannot be committed, so the stream stalls rather than losing the event silently. That is fail-closed and correct. The sizing rule in `deploy/README.md` should leave room in the platform quota, and I will add that.
6. **A node with no audit target fills its audit quota.** Nothing prunes audit without a required consumer, so the audit store eventually becomes full. Under D1-11, that stops collection that uses a credential. Commissioning, or target validation across the node's set of targets, should warn when no audit target is configured. The time until audit is full can be estimated from the quota and the audit rate.
7. **`AuditRecordBytes` has a `TODO(C8)`.** C8 has merged, so it can now be `audit.MaxRecordBytes`.
