# Review of C6 `otsec.syslog/0.1` by A3

- **Contract:** C6, `contracts/syslog/`, PR #42 at `8f96a40`. Owner: A4.
- **Reviewer:** A3 (security), for trust boundary TB5 and threats AP-9, AP-20 and AC-7. Date: 2026-10-24.
- **Scope:** `target.go`, `render.go`, `message.go`, `relp.go` and `doc.go`, plus the C4 addition `time.node-stepped` (D1-16).
  - I did not review the size steps beyond what they mean for security. A6 covers detection accuracy and the golden renderings.
- **Method:**
  - I read the code against the threat model (TB5, AP-9, AP-20, SC-16), C7 and C8.
  - I ran `go test ./contracts/...` at `8f96a40`; it passes.
  - I ran a throwaway probe test inside the package, which I removed afterwards.
  - Evidence class: `desk` (Go 1.26 on Linux). Nothing was run against a collector.

## Outcome: accepted with changes

The core of AP-20 is handled well:
- device bytes go only into escaped SD-PARAM values or base64;
- HOSTNAME is the node ID, and severity is fixed, so a device cannot set either;
- MSG is built from fixed tokens and a narrow character set;
- `ParseRELPResponse` is a small, bounded grammar that fails closed.

Changes 1 and 2 block, because they decide what a forged or misordered acknowledgement can prune and who can inject into the upstream collector. Changes 3 to 5 should land in 0.1. The rest is wording.

## C4 addition

`time.node-stepped` (D1-16) is what C8-A4-5 asked for. It should come from the same detection that writes C8 `clock.change`, so the two cannot disagree. C8 `doc.go` now lists the pair. No change needed.

## Checked and found sound

- **Device content cannot forge structure.** Every device-originated value goes through `add`. If `printable` holds, the value is escaped for `\`, `"` and `]`; otherwise it is base64. PARAM-NAMEs are fixed. `ParseMessage` rejects any second SD element and any control byte. MSG uses `summaryToken`, which excludes `<`, `[`, `]`, `"`, `\` and `=`.
- **No device-controlled header fields.** HOSTNAME is the node ID. APP-NAME, PROCID and MSGID are fixed. Severity is 4 or 5 and never taken from device text. The header time is the node's receive time, never device time.
- **The inbound grammar** matches TB5:
  - TXNR is at most 9 digits with no leading zero;
  - COMMAND is only `rsp` or `serverclose`;
  - DATALEN is at most 4096, with exact DATA;
  - a response for a TXNR that is not outstanding is a violation, and so is a status other than `200 OK` or `500`;
  - after a violation, nothing from that connection is believed.
- **Audit forwarding** (D1-15) is only on required `relp-tls` RFC 5424, with room for a whole sealed record. This matches C8's forwarder properties:
  - `MaxRecordBytes` is stable for 0.x;
  - sealed bytes have no raw CR, LF or NUL;
  - records are never re-encoded.
- **`required` only on `relp-tls`**, and plain RELP is labelled insecure, because its acknowledgements can be forged on the path.
- **Nothing secret is forwarded.** Events carry no credential, no configuration and no transcript. Audit records carry digests only.
