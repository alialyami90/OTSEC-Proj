## Should

**1. Say whether `evidence_class` is an open enum.** D1-23 says "an unknown value reads as `simulated`". `Source.Simulated` says the same, including "a value that only a later minor defines". But `validate.go` refuses any value other than the two, for every minor. So a 0.2 event with a new value is dropped, not read as simulated. Under `contracts/README.md`, a later minor can add enum values only where the contract declares the enum open.

Change: declare the enum open, and accept an unknown value from a later minor, read through `Simulated()`. 0.1 events still take only the two values. Otherwise, remove the later-minor sentence from `Simulated` and from D1-23. A6 prefers the open enum, because it is the reading D1-23 states and it fails toward the weaker claim.

## Outside this PR

**2. No C1 field says that an endpoint is a simulator.** D1-23 sets `evidence_class` "from the C1 endpoint" for received Syslog. C2 sets `Result.target` "from the endpoint's configuration". C1 `Endpoint` has `id`, `transport`, `host`, `port`, `serial_device` and `downstream_security`, and none of them names the far end. As written, the Phase 2 producer would have to take the class from somewhere the contracts do not define. That is where a simulated read could go out labelled `device-observed`.

Change (A2, C1): add a required endpoint field such as `far_end` with the values `device` or `simulator`. Set it at commissioning, and take it as the only source for C2 `target` and C4 `evidence_class`. A6 will then add a chain-test link: a simulator endpoint yields `target` `simulated`, which yields `evc="simulated"`.
