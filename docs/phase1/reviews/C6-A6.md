# C6 `otsec.syslog/0.1`: A6 review

- **Reviewed:** PR #42 at `8f96a40` (`contracts/syslog/`, plus the C4 additions D1-16 and D1-17), A4.
- **Reviewer:** A6, 2026-10-24.
- **Outcome:** **accepted with changes.** Change 1 is required. Changes 2 and 3 should be made. Item 4 answers A4's question to A1.

A6 drove `ParseTarget`, `Render`, `ParseMessage` and `ParseRELPResponse` from a test outside the package, without A4's helpers. Events came from the merged C4 examples. Device text was replaced with hostile content, and the hash, length and span were recomputed so each event still validated. A6 parsed every rendered message a second time with its own RFC 5424 structured-data parser, written in Python from section 6.3 of the RFC, so the check does not rest on A4's `ParseMessage`.

## Required

**1. A required target's `200 OK` means "stored" only if the collector is configured for it, and C5 prunes on it.**

A required `relp-tls` target is the only consumer that makes events prunable (C5 `ComputeBoundary`, D1-5). C6 advances its cursor on `200 OK`. A4's own experiment E-A4-03 (`modules/telemetry/experiments/relp-ack`, trials 1 and 2) shows what that acknowledgement is worth:
- with rsyslog's default in-memory queues, **1,471 of 1,500 acknowledged messages were lost** when the receiver was killed;
- with Direct queues and `confirmMessages="on"`, none were lost.

So with a default collector, the node can prune native records that exist nowhere else. That breaks V-S9 ("zero un-forwarded native records evicted") without any visible failure. Neither `doc.go` nor `A4-contracts.md` states the condition.

Change:
- State in `doc.go` that a target may be declared `required` (and `audit`) only when its collector acknowledges after the message is durably written. Name the configuration E-A4-03 tested as the reference.
- Make that a commissioning check. Send a numbered burst, kill the collector after it acknowledges, restart it, and count. Record the result with the target.
- A6 adds this as a V-S15 case. It runs against the real upstream collector, because the result depends on that collector's configuration, not on the platform.

## Should

**2. Health details can be read two ways.** Each detail is rendered as `hd="key=value"`. `{"a=b": "c"}` and `{"a": "b=c"}` both render as `hd="a=b=c"`. C4 lets detail keys be free text, so a receiver cannot split them back. Change: forbid `=` in health detail keys (C4), or render the key and value as separate parameters.

**3. Bidirectional control characters pass as `dtext`.** `printable` excludes C0, C1, DEL, U+2028, U+2029 and the BOM, but not U+202A to U+202E or U+2066 to U+2069. Device text containing U+202E (right-to-left override) travels as `dtext` and can make a SIEM display reorder what an analyst reads. It cannot forge structure; A6's parser confirmed that. Change: treat those characters, plus U+200E and U+200F, as not printable, so such text travels as `dtext_b64`.

## For A1

**4. LF framing on plain TCP.** A6 sees no reason to remove it. It is best-effort, labelled insecure, and safe only because a rendered message never contains LF, CR or NUL. A6 found no rendering that broke that rule (below). Keep it.

## Checked and found sound

- **Hostile device text** is rendered with one SD element every time, by A6's parser as well as A4's. The probes were:
  - `x"] [evil@1 a="b"`;
  - backslash-quote-bracket;
  - LF, NUL, invalid UTF-8, U+2028 and U+2029, and a BOM;
  - a complete forged RFC 5424 header.

  No message contained LF, CR or NUL. The device text read back equalled the original bytes in every case. Text that cannot travel as printable went as `dtext_b64`.
- **Size.**
  - 1,500 backslashes double when escaped, so the device text is omitted with `TextOmitted` reported, and the message stays within the 2,048-octet limit.
  - 1,500 `]` characters give the same result.
  - Nothing is cut or split.
- **Targets.** All 6 valid targets parse, and all 19 invalid ones are refused. A `required` or `audit` target on anything but `relp-tls` is refused, and so is TLS without `server_name` and `trust_anchor_ref`.
- **`ParseRELPResponse`** gives the right verdict on 19 hand-written frames. Among them:
  - `200 OK` with and without trailing data;
  - `200` without `OK`, and `200 OKx`;
  - a transaction that is not outstanding;
  - TXNR 0, leading zeros, upper-case `RSP`, a double space and CR LF;
  - a 10-digit TXNR and a 5,000-octet DATALEN;
  - `serverclose` with a non-zero TXNR.

  300,000 random frames from the grammar's alphabet caused no panic and no acknowledgement, and never reported more octets used than the buffer held.
- **C4 additions.** `time.node-stepped` is in C4's health types (D1-16), and `Align`'s doc states the repeated-key limit (D1-17). A6 did not probe them further; the C4 re-check covers `Align`.

## Ground truth and independence

- **Independent:**
  - the structured-data parser, which is A6's own;
  - the RELP frames, written from the grammar in `relp.go`'s documentation;
  - the E-A4-03 numbers, which are A4's measurements but answer a question A4's contract does not ask.
- **Same-source:** the C4 example events, which A4 wrote.

Evidence class: `desk` (Go 1.26.0 and Python 3 on Linux). Nothing here ran against a real Syslog collector.
