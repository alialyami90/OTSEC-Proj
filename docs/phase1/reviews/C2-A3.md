# Review of C2 `otsec.adapter/0.1` by A3

- **Contract:** C2, `contracts/adapter/`, PR #51 at `e1d6374`. Owner: A2.
- **Reviewer:** A3 (security), for the credential slot (HR-3, C-17, C-19), AP-23, AP-27, the C7 failed-auth floor (D1-20) and the read-only boundary. Date: 2026-10-24.
- **Scope:** `invocation.go`, `result.go`, `codes.go`, `probe.go`, `doc.go` and the testdata, including the SEL STX/ETX framing.
  - I did not review the parser envelopes beyond their spans. A4 covers those, and A6 covers the ceilings.
- **Method:**
  - I read the code against the threat model, C7 (`contracts/authz`) and the credential design.
  - I ran `go vet ./contracts/...` and `go test ./contracts/adapter` at `e1d6374`; both pass.
  - I ran a throwaway probe test inside the package. It rebuilds the valid examples with one rule broken at a time and calls `Result.Validate`. I removed it afterwards.
  - Evidence class: `desk` (Go on Linux). Nothing was run against a device or a simulator.

## Outcome: accepted with changes

The structure is right:
- the collector builds the invocation itself, and invocations are strict;
- the transcript covers every byte exactly once, with hash and phases;
- the redaction marker is fixed, and no hash of the secret is stored;
- QUI is never sent after a rejected password;
- identity is checked before authentication in the examples;
- spans point into received bytes only and never include framing.

The examples are honest. The README says every transcript is invented, every result has target `simulated`, and the `ID` checksums are placeholders.

The gap is that the result validator checks the session facts (`password_prompt`, `access_level` and so on) as flags, not against the bytes. `doc.go` lists the slot rule, the prompt-before-line rule and the nothing-after-a-failed-password rule under "Rules the types enforce". `Validate` accepted every one of the probes below. A6 needs the validator as its oracle for "no unauthorized write" and "one password attempt", and the collector needs it as the last check before a result leaves. So changes 1 to 4 block. Change 5 is A1's blocking item 1, which I agree with.

## STX/ETX framing

I agree with stripping NUL, XON, XOFF, STX and ETX before prompt and grammar matching, keeping them in the transcript, and keeping them out of every span. `span-includes-stx` tests the last rule. Four points:

- The framing makes change 4 easy. ETX is a reliable end-of-message marker, so "a prompt at line start or right after ETX" is a strong rule even before the prompt position is confirmed.
- Nothing the platform sends can contain a framing byte. The register parameter grammar is `[A-Z0-9/]`, and the C7 SEL-751 secret policy allows only `[!-~]`. Please add a one-line test that the egress check refuses a sent line containing 0x00, 0x02, 0x03, 0x11 or 0x13, so this is not left to coincidence.
- The assumed prompt after ETX and the invented transcripts are correctly labelled. They should stay assumptions in the capability matrix until a capture exists. The examples are contract fixtures, not parser fixtures, and the README says so.
- When the capture is taken (A6 H-12, H-13), it should also show whether the password is echoed, and whether `Password: ?` is framed. Change 1(b) and change 8 depend on both.

## What I checked and found right

- `CheckAgainst` refuses a credential where C1 does not allow one, and refuses limits looser than the profile.
- The credential reference syntax is kept equal to C7's by `TestCredentialRefMatchesC7`.
- `SuspendsCredential` is set only where the password was sent: `failed.auth_rejected`, `failed.unexpected_access_level` and `failed.identity_mismatch`. This matches C1-A3-5.
- `refused.password_prompt_absent` sends no credential and then QUI. This matches C7-A2 change 3.
- `refused.language_not_english` sends no QUI (D16), and `refused.session_elevated` sends nothing but the wake.
- Connect retries stop once a byte has been sent, and authentication is never retried.
- An unknown code reads as `failed.unknown`, and a result with one is not ok.
