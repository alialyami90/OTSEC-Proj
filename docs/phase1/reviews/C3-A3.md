# C3 `otsec.register/0.1`: A3 security review

Reviewer: A3. Date: 2026-10-24. Reviewed: PR #27, commit 200688c (`contracts/register/`). The review covers security-sensitive behaviour: the C-A2-1 and C-A2-2 conditions, the envelope that C7 verifies, and whether the format can express an unrestricted line. A6 owns the deny-corpus gate.

**Outcome: accepted with changes C3-A3-1 and C3-A3-2. Both are needed before merge, because C3-A3-1 changes the bytes a release key signs.** C3-A3-3 to C3-A3-6 are notes that need no change before merge.

## The five points A1 asked about

1. **Templates contain no regex and no free text: confirmed.** A line is `[A-Z0-9]+` tokens separated by single spaces. Parameters are typed: `uint` with mandatory bounds and no leading zeros, or `enum` with `[A-Z0-9]+` values. `Render` rejects missing, extra or out-of-range values, and `Match` accepts a line only when re-rendering it gives back the same bytes. A rendered line therefore cannot contain a control byte, lower case, punctuation or a second command. Deny rules are regular expressions, but they only widen what is refused. `Match` checks them before anything else, so they can never approve a line.
2. **Session-control lines are separate and never invocable: confirmed (C-A2-1).** They sit in their own list with a fixed classification and the phases that may send them. In the SEL-751 data, `ACC` is auth-only and `QUI` is probe and close, which matches A3 §8.3 as updated in PR #14. `Matcher.Operation` returns operations only. A3 probed it with `sel.session.acc` and got not-found. C7's `RunBody.ValidateAgainst` refuses anything that is not `read-only` as a second check.
3. **The firmware allowlist is inside the package and fails closed: confirmed (C-A2-2).** A FID must match a `Known` entry exactly, its branch must have a rule, and a denied branch or a version below the minimum is refused. Conditions such as `EHTTP := N` come back with the rule. The caller must confirm them, and C2 and C8 must record a refusal when it cannot.
4. **Envelope shape: accepted, with a change to what is signed (C3-A3-1).** The fields contract, algorithm, key ID, payload and signature are what C7 needs. A separate digest or floor field is not needed, because the revision sits inside the signed payload.
5. **`Revision` as the anti-rollback counter: accepted,** with the per-family rule in C3-A3-4.

| C3-A3-1 | `Signature` is over the raw `Payload`, with no domain separation. Release keys may also sign other artifacts (node software releases, policy bundles: C-A5-2). C3's `Signature` comment then refers to it. | A signature over the bare payload, or over the same payload with another context string, is rejected by C7. |
| C3-A3-2 | **`Decode` accepts duplicate keys and some trailing data.** A3 probed PR #27 directly. A package with `"line": "SER", "line": "SER"` decodes, and Go keeps the last value. ## Notes, no change needed before merge

- **C3-A3-3, payload size.** Neither the envelope nor the package has a size bound. C7 will cap the payload at 1 MiB before parsing. The current SEL-751 package is about 60 KiB.
- **C3-A3-4, anti-rollback is per family, and an equal revision means identical bytes.** C7 persists, for each `Family`, the highest accepted revision and the SHA-256 of that payload. A lower revision is refused. An equal revision is accepted only if its bytes are identical, so two different packages can never share a revision. The collector selects the package whose `Family` equals the asset's C1 family and applies only that package's firmware allowlist. Suggest that the `Revision` comment say "per family".
- **C3-A3-5, deny cross-check samples only the bounds of `uint` parameters.** A deny rule that matches a middle value would not make the package invalid. This is not a runtime gap, because `Match` checks deny rules on every real line first. It belongs in A6's deny-corpus gate rather than in a change to C3.
- **C3-A3-6, `ID` is an invocable operation and also the transport's probe step.** That is consistent: the transport reads the FID in the probe phase (A3 §8.3), and an adapter may also invoke `sel.id` after authentication. Both are read-only at Level 0 (S22 Table 7.43).

## Re-check of the fixes (6a2299e, 2026-10-24)

- **C3-A3-1: closed.** `register.SigningDomain` is `"otsec.register/0.1 package\n"`, and the `Envelope.Signature` comment and the schema both say the signature covers the domain followed by the payload. C7 builds `authz.RegisterSigningInput` from this constant, so the prefix is defined only once.
- **C3-A3-2: closed.** A3 re-ran its own probe against 6a2299e. The duplicate `line` key and the trailing `]` are both rejected now, and the package's tests pass. One note, no change needed: the strict-JSON walk has no depth limit. C7 caps the payload at 1 MiB, and verifies the signature before any parse, so only a release-signed payload ever reaches it.

**Outcome now: accepted.**

## Second re-check: operation phases and posture warnings (dfe829e, 2026-10-24)

A2's review added two format changes: an operation may now also run in the probe phase, before `ACC` (only `sel.id` does), and there is a new egress check, `Matcher.Permit(phase, line)`. Posture warnings (MAXACC, FTPACC, HTTPACC) now ship inside the signed package. The probe change widens what may be sent before authentication, so A3 probed dfe829e directly.

**Outcome: accepted with one change, C3-A3-7, needed before merge.** It is a validation rule only. The SEL-751 data already meets it, so no signed content changes. C3-A3-8 to C3-A3-10 are notes.

| ID | Finding | Change | Test |
| --- | --- | --- | --- |
| C3-A3-7 | **A probe operation may declare an access level above 0.** A3 marked `sel.ser.read_all` (`SER`, level 1) as `phases: ["probe"]`, and the package still validates. Probe lines are sent before `ACC`. On a relay whose port is already elevated (D18) or whose Level 1 password is disabled (D26), a Level 1 line in the probe phase would run with no authentication at all. The literal-only rule does not prevent this. | `Validate` refuses an operation that lists `probe` unless its `access_level` is exactly `"0"`. | Golden negative: a literal level 1 operation marked `probe`. |

### Notes, no change needed

- **C3-A3-8, a probe-only operation is still returned by `Matcher.Operation` and `Matcher.Render`.** `Permit` then refuses it in the operate phase, so nothing reaches the device, but a schedule could name it. C7 now refuses it first: `RunBody.ValidateAgainst` returns `not_invocable` unless the operation runs in `operate`, with a test. C7 also renders through `Matcher.Render`, so the deny rules apply at request time as well as at egress.
- **C3-A3-9, `Permit` cannot know the device's current level.** The phase is the transport's idea of the session, not the relay's. The transport must see the Level 0 prompt (`=`) before it sends any probe line. If the first prompt is already elevated, it sends nothing more, closes, and suspends the asset with `unexpected-access-level` (D18). This is a C2/C6 requirement. A3 will check it in those reviews.
- **C3-A3-10, posture warnings fail safe.** `Raised` treats a value that is not a decimal number as raised, so an unreadable setting is reported rather than passed. The empty string is also raised. One caller rule for C2: a setting that is missing from the `SHO P 1` output must also be reported as raised, never skipped. Warnings sit inside the signed payload, so removing one needs the release key and is visible in the package diff.
- **Accepted as they are:** `Permit` as the single egress check for every line the transport sends, whoever produced it. `Matcher.Render` refusing a line that does not classify as its own operation. Only the exact JSON tag spellings are accepted, and keys are compared case-insensitively for duplicates (A3 re-ran the misplaced-key and duplicate probes). The number of probe operations is not limited; with C3-A3-7 and the release signature, that is acceptable.

**Outcome now: accepted once C3-A3-7 lands.**
