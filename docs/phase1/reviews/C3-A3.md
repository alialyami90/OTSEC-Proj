# C3 `otsec.register/0.1`: A3 security review

Reviewer: A3. Date: 2026-10-24. Reviewed: PR #27, commit 200688c (`contracts/register/`). The review covers security-sensitive behaviour: the C-A2-1 and C-A2-2 conditions, the envelope that C7 verifies, and whether the format can express an unrestricted line. A6 owns the deny-corpus gate.

**Outcome: accepted with changes C3-A3-1 and C3-A3-2. Both are needed before merge, because C3-A3-1 changes the bytes a release key signs.** C3-A3-3 to C3-A3-6 are notes that need no change before merge.

## The five points A1 asked about

1. **Templates contain no regex and no free text: confirmed.** A line is `[A-Z0-9]+` tokens separated by single spaces. Parameters are typed: `uint` with mandatory bounds and no leading zeros, or `enum` with `[A-Z0-9]+` values. `Render` rejects missing, extra or out-of-range values, and `Match` accepts a line only when re-rendering it gives back the same bytes. A rendered line therefore cannot contain a control byte, lower case, punctuation or a second command. Deny rules are regular expressions, but they only widen what is refused. `Match` checks them before anything else, so they can never approve a line.
2. **Session-control lines are separate and never invocable: confirmed (C-A2-1).** They sit in their own list with a fixed classification and the phases that may send them. In the SEL-751 data, `ACC` is auth-only and `QUI` is probe and close, which matches A3 §8.3 as updated in PR #14. `Matcher.Operation` returns operations only. A3 probed it with `sel.session.acc` and got not-found. C7's `RunBody.ValidateAgainst` refuses anything that is not `read-only` as a second check.
3. **The firmware allowlist is inside the package and fails closed: confirmed (C-A2-2).** A FID must match a `Known` entry exactly, its branch must have a rule, and a denied branch or a version below the minimum is refused. Conditions such as `EHTTP := N` come back with the rule. The caller must confirm them, and C2 and C8 must record a refusal when it cannot.
4. **Envelope shape: accepted, with a change to what is signed (C3-A3-1).** The fields contract, algorithm, key ID, payload and signature are what C7 needs. A separate digest or floor field is not needed, because the revision sits inside the signed payload.
5. **`Revision` as the anti-rollback counter: accepted,** with the per-family rule in C3-A3-4.

## Changes

| ID | Finding | Change | Test |
| --- | --- | --- | --- |
| C3-A3-1 | `Signature` is over the raw `Payload`, with no domain separation. Release keys may also sign other artifacts (node software releases, policy bundles: C-A5-2). A signature made for one artifact whose bytes happen to parse as a register package could then be replayed as a register. | Sign `"otsec.register/0.1 package\n"` followed by the payload bytes. C7 defines this signing input and owns the constant (`authz.RegisterSigningInput`). C3's `Signature` comment then refers to it. | A signature over the bare payload, or over the same payload with another context string, is rejected by C7. |
| C3-A3-2 | **`Decode` accepts duplicate keys and some trailing data.** A3 probed PR #27 directly. A package with `"line": "SER", "line": "SER"` decodes, and Go keeps the last value. A reviewer or another tool may show the first. A package followed by `]` also decodes, because `dec.More()` does not catch a closing delimiter. A signed package must mean exactly one thing to everyone who reviews it. | Reject duplicate keys at any depth. Require `dec.Token()` to return `io.EOF` after the package. C7 runs its own duplicate-key check on the payload before calling `Decode`, but `Decode` should be strict for every reader, including A6's tools. | Golden negatives: a duplicate `line` key, and a trailing `]`, are both rejected. |

## Notes, no change needed before merge

- **C3-A3-3, payload size.** Neither the envelope nor the package has a size bound. C7 will cap the payload at 1 MiB before parsing. The current SEL-751 package is about 60 KiB.
- **C3-A3-4, anti-rollback is per family, and an equal revision means identical bytes.** C7 persists, for each `Family`, the highest accepted revision and the SHA-256 of that payload. A lower revision is refused. An equal revision is accepted only if its bytes are identical, so two different packages can never share a revision. The collector selects the package whose `Family` equals the asset's C1 family and applies only that package's firmware allowlist. Suggest that the `Revision` comment say "per family".
- **C3-A3-5, deny cross-check samples only the bounds of `uint` parameters.** A deny rule that matches a middle value would not make the package invalid. This is not a runtime gap, because `Match` checks deny rules on every real line first. It belongs in A6's deny-corpus gate rather than in a change to C3.
- **C3-A3-6, `ID` is an invocable operation and also the transport's probe step.** That is consistent: the transport reads the FID in the probe phase (A3 §8.3), and an adapter may also invoke `sel.id` after authentication. Both are read-only at Level 0 (S22 Table 7.43).
