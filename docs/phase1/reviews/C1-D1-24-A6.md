## Should

**1. An observation is not tied to the endpoint it came through.** The cross-check is per asset: a simulator observation needs some endpoint whose target is `simulated`, and a device-observed session value needs some `device-observed` endpoint.

On an asset with one endpoint of each kind, A6's probe adds a `device-observed` adapter-session value that the simulated endpoint produced. It validates, because the observation names only the session, not the endpoint.

Such an asset is unusual, for example a lab relay with a simulator alongside it. When it occurs, though, principle 10 depends on knowing which endpoint a value came through. Change: an adapter-session or Syslog observation carries its endpoint ID, and its evidence class must equal that endpoint's target. Alternatively, `Validate` refuses an asset whose endpoints have mixed targets.
