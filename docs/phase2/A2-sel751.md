# A2: the SEL-751 adapter (P2-A2)

Owner: A2. Code: `modules/ied/telnet`, `modules/ied/sel751`. Contracts used: C1, C2 0.1, C3 0.1 (register revision 2). Evidence class of everything here: **simulated**. No device has been contacted.

## Entry point

`sel751.Run(ctx, adapter.Invocation, sel751.Config) adapter.Result` is the only entry point. It never returns a Go error. The collector (A3) runs `Validate`, `CheckLines` and `CheckAgainst` on every result before using it. `Config` is the seam agreed with A3 on #75:

- `FloorGate.BeforeACC` is called before ACC, and ACC is written only after it returns nil.
- `FloorGate.Confirmed` is called on `=>` after ACC, whether or not the password was sent.
- `Secret.Use` is the single-use credential slot. `Secret.EchoSpans` finds an echo of the secret, so the adapter never compares the secret itself.
- `Dial` is the collector's dialer.

## The dialogue

| Step | Sent | Phase | Condition to go on | Otherwise |
| --- | --- | --- | --- | --- |
| Checks | nothing | none | register valid for the family; `ValidateWith` and `CheckAgainst` pass; a reader exists for the operation; the declared FID is on the allowlist; the credential slot fits the operation's level | the C2 code; nothing is dialled |
| Connect | `\r\n` (wake), only if nothing arrives within 1 s | probe | first prompt `=` | `=>` or `=>>`: `refused.session_elevated`. `Password: ?` before the wake: `refused.session_pending_password`. Both send nothing more. |
| Language probe | `QUI` | probe | the reply matches the C2 probe grammar | `refused.language_probe_rejected`; nothing more sent (D16) |
| FID gate | `ID` (rendered from `sel.id`) | probe | the FID equals the declared FID exactly | `refused.identity_mismatch`. An unreadable ID reply is a mismatch with nothing observed. |
| Floor | nothing | none | `BeforeACC` returns nil | `failed.internal`; ACC not sent |
| Auth | `ACC` | auth | `Password: ?` | `=>`: `Confirmed`, then `refused.password_prompt_absent` and QUI (AP-23). `=` or `=>>`: `failed.unexpected_access_level` and QUI. A timeout or a close: nothing more sent. |
| Credential | the secret, via `SendSecret` | auth | `=>`: `Confirmed` | `Password: ?` again, or `=`: `failed.auth_rejected` with no QUI (C-19). `=>>`: `failed.unexpected_access_level` and QUI. A timeout or a close: nothing more sent; the floor stays set. |
| Checks read | `SHO P 1` (every `read_by` of the register's preconditions, the branch's conditions and the warnings) | operate | `LANG := ENGLISH`, then the warnings, then the branch conditions | `refused.language_not_english` (no QUI, D16) if the reply does not parse or LANG is not ENGLISH; `refused.firmware_condition_not_met` and QUI |
| Operation | `SER` | operate | one framed message | `failed.device_error` (no report), `failed.identity_mismatch` (SER header serial), `partial.read_rows_exceeded`, `partial.parse_errors`, all with QUI |
| Close | `QUI` | close | any prompt, or one step timeout | none |

Every line goes through `telnet.Conn.Send`. Its egress check passes a line only when all of these hold:
- the step means to send exactly that line;
- the register's `Matcher.Permit` allows it in the current phase;
- in the operate phase, it is the invocation's operation or a read that one of the register's checks names.

The password goes only through `SendSecret`, inside `Secret.Use`, and only straight after `Password: ?`. The wake goes only through `SendWake`, which works once and only before any other line.

### When QUI is sent

QUI is sent when the session reached Level 1 and a level prompt makes it safe, or when an `ok` Level 0 read ends. After a timeout or `response_too_large` it is sent with no prompt before it, but only once `=>` or `=>>` confirmed ACC and the password (C2 dialogue rule).

QUI is never sent in these cases:
- after a rejected probe;
- on a non-English port;
- to a session that was elevated or at a password prompt on connect;
- after a password that no prompt confirmed;
- after the level drops.

If QUI is owed but the connection has gone, the result is `failed.transport_closed`, and the detail names the outcome that came before.

### Prompts

The adapter acts on C2's prompt rule, copied in `prompt.go`. The rule looks at the end of the reply: a prompt counts only first in the reply or after CR, LF, STX or ETX, and NUL, XON, XOFF and trailing spaces are ignored. The adapter also waits a quiet interval with nothing received.

I tried a stricter rule that ignored a prompt inside an open STX message. Fuzzing showed it produced results that `Validate` refuses, because the transcript then shows a prompt the adapter did not act on. Narrowing the rule is C2's change to make once a capture shows where the prompt sits (H-13).

### Reporting

These rules make every C2 golden replay exactly.
- **Observations** (`firmware_id` and `sel.cid` from ID, `serial_number` from the SER header) are reported only when the status is `ok` or `partial`. For an identity mismatch, only the value that differed is reported, as evidence for the suspension. A session that did not complete does not update the C1 asset.
- **Posture warnings** are reported once SHO P 1 shows an English port, whatever the outcome. They are not reported on a non-English port, where none of the output is interpreted (D16).
- **Records** are reported only with `ok` or `partial.parse_errors`. With `partial.read_rows_exceeded`, no row is parsed (D1-12).
- **An empty SER buffer** prints `No Data Available` (A6's transcription of S22 p. 7.75). It is `ok` with no records and no serial item. The FID read before ACC is the identity check.
- **ID line checksums** are parsed but not enforced. The FID must equal the declared FID exactly, so a corrupted line fails that check anyway. Figure 3.20 has six lines whose printed checksums do not hold, so enforcing them risks refusing a healthy relay until a capture settles it.

## Timing choices (not in the manual; H-13)

- **Quiet interval:** 200 ms after a prompt before acting on it.
- **Wake wait:** 1 s of silence on connect before the wake.
- **Close allowance:** 4 KiB beyond `max_response_bytes` for the QUI reply, so a session stopped at the limit still ends with QUI. The close step may run one step timeout past the deadline for the same reason (D18).
- **Telnet negotiation:** at most 64 commands per session. A read timeout does not end the session.

## C2 examples amended in this change

- `failed.internal`: the fault is now the floor gate after ID (`BeforeACC` fails, so ACC is not sent). This is the path `Run` actually has. The old example stopped after the probe, a point where no fault exists in `Run`.
- `ok-missing-setting`: now matches `ok` in everything except the missing setting. It gains the serial identity item, the observations and the records it lacked.

## C2 0.2 proposal: two gaps in the QUI rule (for A1, A3, A6)

In each of these, no result exists that both follows the safety rule and passes `Validate`. `Run` follows the safety rule. The collector then quarantines the result (#82) instead of using it. `FuzzRun` skips these cases by name (`c2Gap`) and fails on anything else. Both cases are fuzz finds, and their inputs are kept in `testdata/fuzz/FuzzRun`. Neither has been seen on a device. Both are device states that the manual does not describe for these replies.

The rule in question is in `contracts/adapter/dialogue.go`: "A session that reached Level 1 ends with QUI (D18, V-S13)", with four exempt codes.

### Gap 1: `Password: ?` at Level 1

A reply to SHO P 1 or SER ends in `Password: ?`. Anything sent now is a password attempt, so QUI would be a second attempt (C-19). D18 still wants QUI, because the session reached Level 1.

Today `Run` sends nothing more and closes the transport. It returns `failed.internal`, with the detail `an unexpected password prompt; nothing more sent`, and `Validate` refuses that result.

**Proposal.** Add a code, exempt it from the QUI rule, and require the bytes to back it:

```go
FailedUnexpectedPasswordPrompt Code = "failed.unexpected_password_prompt" // "Password: ?" after Level 1: nothing more sent, no QUI (C-19)
...
case FailedTransportClosed, FailedAccessLevelDropped, RefusedLanguageNotEnglish, RefusedSessionElevated,
	FailedUnexpectedPasswordPrompt:
...
if code == FailedUnexpectedPasswordPrompt && (last != promptPassword || quit) {
	c.fail("%s: the last prompt received is %q, and nothing is sent after it", code, promptPassword)
}
```

- **A distinct code.** A1 leaned towards a distinct code, and I agree. Reusing `failed.unexpected_access_level`, my first idea, would hide a credential-relevant state behind a code that means something else.
- **`failed`, not `refused`.** The session was underway and stopped on a device state it did not expect. In C2's stages, `refused` is the adapter declining before it acts. If A1 prefers `refused`, nothing else in the proposal changes.
- **The collector.** The session ends without QUI at Level 1. A3's PR 3 sets the failed-auth floor again after an exit without QUI, so a session of this kind is followed by the floor wait and is not retried at once.

`Run` changes one line once the code exists: it returns the new code in place of `failed.internal`. A golden for the new code would go in the same change.

### Gap 2: a probe reply that shows `=>` or `=>>`

The language probe's reply prints a level prompt above 0. D16 sends nothing after a rejected probe, not even QUI, because the port's commands are not known. D18 wants QUI once a prompt above 0 was seen.

Today `Run` returns `refused.language_probe_rejected`, with the QUI probe as the last line sent, and `Validate` refuses that result.

**Proposal.** Add `RefusedLanguageProbe` to the exempt codes, as `RefusedLanguageNotEnglish` already is. D16 already requires the QUI probe to be the last line sent, so the bytes are bound. No new code is needed.

### What is not proposed

- Narrowing C2's prompt rule (a prompt inside an open STX). That waits for a capture (H-13).

## Evidence

All of it is simulated or documentary. Linux container, Go 1.26.

- **Replays:** `TestReplayGoldens` replays 22 C2 goldens through a scripted far end. The far end checks every sent byte, with the secret on the wire and the marker in the transcript. The result must equal the golden apart from times, the build version and an unstated detail. It must also pass `Validate`, `CheckLines` and `CheckAgainst`, and the floor calls must match.
- **Before connecting:** `TestBeforeConnect` covers 9 more refusals.
- **Not replayed:** four goldens are decided by the collector and one is a 0.2 read case. `TestEveryGoldenAccountedFor` lists each with its reason.
- **Level 0:** `TestLevel0ID` and `TestLevel0WithoutDeclaredFID`.
- **Egress:** `TestEgressRefusesUnregistered` uses an oracle written out from the register: 48 lines in 4 phases. Only the 6 phase and line pairs on the list are written. `TestEgressHoldsTheStepsLine` checks the step's own line. `FuzzEgress` ran 60 s with no failure.
- **Whole-dialogue fuzz:** `FuzzRun` drives the dialogue against random far ends. It found five cases where the result failed `Validate`. Three were fixed in the adapter, and two are the C2 gaps above. After that it ran 3 min (about 25,000 runs) clean. The five inputs are kept in `testdata/fuzz/FuzzRun`.
- **Parsers:** `FuzzFrame`, `FuzzParseID`, `FuzzParseSER` and `FuzzParseSettings` each ran 60 s with no failure (#85).
- **A6's simulator:** `TestSimulator` ran against `sim.py --profile sel-751-doc` at #76 `e3cf625`, in 8 scenarios:
  - ok;
  - wrong password;
  - password disabled;
  - R402 with EHTTP := Y;
  - empty SER;
  - FID mismatch;
  - Level 0 ID;
  - no STX/ETX.

  It also ran with `--profile-inherit level`. Every scenario gave its expected code. `check.py` against `sel751-collector-register.json` found no violations, and the wrong password counted exactly one failed attempt.

  With `--profile-inherit prompt`, the simulator greets with `=` while a password is pending. `Run` then sends the QUI probe, and the simulator records it as a password attempt. Only the C7 floor prevents this, by design (reported on #76).

## Limitations

- **Untested on hardware:** the probe reply, the echo, where the prompt sits after ETX, the SHO P 1 layout, `No Data Available`, and what a new connection inherits (H-12, H-13, H-15).
- **Not built:** `DATE_F` is not read yet; it needs a C3 change to read `SHO G`. There is no SSH, no serial and no SER arguments.
- **Windows:** `go vet` and `go test -c` cross-build cleanly. The native run is the `go (windows-latest)` CI job (D2-13).
