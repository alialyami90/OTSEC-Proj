# A4: C6 `otsec.syslog/0.2` (A1 D2-9)

- **Package:** `contracts/syslog`. A minor revision of C6; the rules are in its package doc and on `DurableAck`.
- **Evidence class:** `desk`. The collector behaviour it rests on is A6's container run with rsyslogd 8.2312.0 and librelp 1.11.0 (D2-9). No collector was configured or contacted for this change.

## What changed

| Item | 0.1 | 0.2 |
| --- | --- | --- |
| `durable_ack.peer_check` | absent | required, closed: `"name"` only. The collector checks the node certificate's CA chain and its name against a permitted-peer list (imrelp `tls.authmode="name"` with `tls.permittedPeer`). `certvalid` is refused. |
| `durable_ack.permitted_peer` | absent | required: the listener's whole permitted-peer list, which must be exactly one name, this node's certificate name: `^[A-Za-z0-9][A-Za-z0-9._-]{0,252}$`, no wildcard. A collector shared by several nodes gives each node its own listener (A3 S-1). |
| `durable_ack.ack_after` | absent | required, closed: `"durable-write"` only. The receiving ruleset writes synchronously before it answers (rsyslog `queue.type="Direct"` and omfile `sync="on"`). |
| `Identifier` | `otsec.syslog/0.1` | `otsec.syslog/0.2`; rendered messages carry `v="otsec.syslog/0.2"`. |
| `ParseAudit` | accepted `0.1` only | accepts any `0.x` (D1-13), refuses another major. |

All three fields fail with `CodeDelivery`, on every required target, whatever minor it declares. A required target written for 0.1 has not shown that the collector refuses writers other than this node, or that a 200 OK means stored, so under 0.2 it no longer holds back pruning until it is re-commissioned. Best-effort targets are unchanged, and still may not carry `durable_ack`.

## What Validate can and cannot check

The fields are what the commissioning record attests. Validate checks their form; it cannot check the collector. The record itself must show the three refusals A6 lists in V-S6 (`docs/verification.md`): no client certificate, a CA-signed certificate for another name, and a self-signed certificate with the permitted name. The forwarder checks at load that `permitted_peer` equals the name in the node's own client certificate, so a `durable_ack` copied from another node's target fails (A3 S-2, A6).

## Compatibility

- **Readers:** a 0.2 reader accepts 0.1 targets and messages, except a required 0.1 target without the new fields, which is refused on purpose (above).
- **Writers:** a 0.1 reader refuses a 0.2 target (unknown fields under strict decoding). Only the node reads targets, so all nodes move together.
- **Rendered goldens:** the only change is `v="otsec.syslog/0.1"` to `0.2` in the seven files under `testdata/rendered`.
- **A6 fixtures:** the three new fields were added to the required targets in `tests/contract` (`c4c6_evidence_class_test.go`, `c6_test.go`, `chain_session_test.go`), with A6's agreement.

## The forwarder side

D2-9 also asks the forwarder to check the collector by name. That is in the forwarder PR (P2-A4 part 2), not here: the TLS dial sets `ServerName` to the target host and verifies the chain and SPKI pins, with no `InsecureSkipVerify`.
