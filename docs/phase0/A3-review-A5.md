# A3 trust-boundary review of A5's Phase 0 findings (PR #3)

Reviewer: A3, per the cross-review table (A5 platform → A3 trust boundaries). Date: 2026-10-23. Reviewed: `docs/phase0/A5-platform-feasibility.md` on branch `claude/project-thread-xni3ff` (sections 2, 5, 6, 7, 9, 12). Not reviewed: the Go experiment code beyond what the findings cite (A6 owns reliability review).

**Verdict: accepted for Phase 0, with the conditions below carried into the Phase 1 site-to-central contract (C-series, with A5 as co-owner).** None blocks merging the findings document. Conditions 1–4 are security requirements for the contract text. Conditions 5–9 are hardening and test items.

## What holds

- Site-initiated mTLS, no WAN listener, no exec channel, replay from the local store only, offline-signed releases with an anti-rollback floor, and credential references only on central. These match threat-model TB2, AP-7, AP-8, and AP-10.
- **Collector out of process (section 2): accepted, and A3 asks that it be mandatory rather than optional.** One OS user and process alone reads device credentials and alone has a route to the IED network. This is how TB4 is enforced, and it means a compromised UI or API process has neither credentials nor a path to IEDs.
- Separate quotas per stream class, with drop-and-count persisted and forwarded. This matches AP-19.
- `CAP_NET_BIND_SERVICE` for the port-514 listener instead of root (section 12).

## Conditions

| ID | Finding | Required change | Test |
| --- | --- | --- | --- |
| C-A5-1 | Section 2 makes the collector process the credential and IED-route boundary but does not say how "alone has a route" is enforced. | Enforce at the OS: only the collector's UID may send on the IED-facing interface (an owner-match firewall rule or a dedicated network namespace). The L4 egress check runs inside the collector. The Syslog listener runs outside the collector, with no credential access. | From the UI/API user, attempt a TCP connection to an IED address → refused by the host. From the collector user → allowed only to register ports (L6). |
| C-A5-2 | Section 6 says central delivers "signed" bundles but not who holds the signing key. If central's online services can sign, a compromised central (AC-6) can sign any bundle inside the site ceiling. | The policy signing key is separate from central's TLS identity and is not usable by central's online services alone, for example an administrator-held hardware key with second-approver policy for widening changes. Central relays signed bundles; it does not mint them. The site ceiling, set at enrollment, still bounds everything. | A bundle signed by central's TLS key, or by any key other than the policy key → rejected and alarmed. |
| C-A5-3 | Section 6 lets central set **forwarding targets**. A compromised central could redirect a site's OT telemetry and audit to an attacker host (AP-9 exfiltration) or drop the real target (blinding). | Forwarding targets must come from a site-local allowlist fixed at enrollment or changed only with site-side approval. Each target's certificate is pinned. Removing a `required` target is a policy-widening change (second approver). | A bundle adding an unlisted target → rejected. Removing the required target without a second approval → rejected. |
| C-A5-4 | Section 6 says HTTPS "passes the proxies and firewalls utilities already run". Many utility proxies intercept TLS. | Nodes trust only the dedicated enrollment CA for central, never the OS trust store. A TLS-intercepting proxy must be bypassed for this connection; nodes are never configured to trust a proxy CA. This must be written into the deployment guidance. | A node behind an intercepting proxy fails closed with a specific local alarm ("central identity mismatch"), not a generic "unreachable". |
| C-A5-5 | **Intel AMT v11 on the SEL-3355-2, reachable through ETH1** (section 12). This is out-of-band management below the OS: a remote-control path that bypasses every OS-level control in this design. | AMT disabled in firmware at commissioning (preferred). Failing that, ETH1 is connected to no network. Never use ETH1 for the IED-facing or WAN interface. Threat model AP-24. | Commissioning check from an adjacent lab host: no AMT service answers on the node's interfaces (the AMT TCP ports 16992–16995, and AMT's IPMI-style port 623). Record the firmware setting in the commissioning record. |
| C-A5-6 | Clock as an integrity dependency (sections 6, 12). The node's time sources (NTP, IRIG-B, SEL-2488 Syslog) are unauthenticated in the documented SEL setups. A spoofed time source can expire certificates (site lockout), push mTLS outside validity, or skew evidence timestamps. | Bounded step acceptance: a step larger than a configured threshold, or any backwards step, is not applied silently. It is alarmed and audited (`clock.change`). Certificate validation failures caused by the clock are reported as clock faults. | Inject a 2-day forward step from the time source → node alarms, keeps last good time for TLS decisions, and audits the event. |
| C-A5-7 | Certificate lifetime (section 6): 90 days, renewal at one third, operator-approved re-enrollment after expiry. | Accepted as proposed. Add: revocation is enforced by central refusing the node certificate. Central's own certificate rotation must chain to the pinned enrollment CA, or nodes refuse it. | Revoked node certificate → refused on next connect. Central certificate not chaining to the pinned CA → node refuses. |
| C-A5-8 | Local UI and API on the site management interface (R8.3). | Same RBAC as central, and it must work offline (locally cached accounts, or a documented break-glass account that is audited and alarmed on use). In slice 1, no local UI action may cause device I/O (AP-15). Bind to the management interface only, as already proposed. | Local UI with WAN down: login works with cached accounts; break-glass use raises an alarm on reconnect. |
| C-A5-9 | Windows is listed as a supported node OS (section 12). Section 7's hardening is systemd-specific. | For any node with an IED-facing interface, recommend Linux. If the owner runs Windows, an equivalent hardening profile (service accounts, firewall per service, AppLocker or WDAC) must be specified and verified before use. | n/a until the owner chooses. |

## Notes, no change required

- Replay requests from central should be rate-limited so a compromised central cannot use replay to load the node or the WAN. Low risk, as replay never touches a device.
- `audit.db` is writable by root on the node. This is AP-17's residual window, now stated in the threat model. The SEL-3355-2's TPM 2.0 is a candidate anchor (TPM-bound monotonic checkpoints), to evaluate in Phase 1.
- The TPM also satisfies B-04's preference for a node-bound credential-store key on this hardware. Nodes without a TPM fall back to a root-only key file, recorded as weaker.
